# Test fixtures

Small committed files that Folioxide's tests and oracles read. The policy below is the one in
`docs/ARCHITECTURE.md` §A.9 ("Fixtures policy").

## License policy

- **Generated by this project.** Every file in this directory is produced by this project's own
  generators (or written by hand for it, or written by an external tool such as qpdf from a
  document this project's script builds; the row says which) and is licensed **`MIT`**, like
  the code. The only exception would be a row in the table below that names a different license.
- **External corpora are never committed.** Test suites from other projects (pdf.js, PDFBox,
  hayro-tests and the like) carry mixed or unclear licenses. They stay outside the repository and
  are used only through the opt-in corpus smoke test (`FOLIOXIDE_CORPUS=/path`).
- **Fonts:** fonts under the SIL Open Font License (OFL) may be committed as **test data only**:
  embedded into test PDFs, never shipped in a crate or npm package. Each one gets its own row with
  its source URL and the OFL license text next to it.
- **Generate, don't commit, where possible.** Prefer fixtures that `folioxide-testkit` builds at test
  time or that `cargo xtask fixtures` regenerates. A committed file must stay **under 200 KB**.
- **Every committed file has a row below** (a group may share one row). Add the row in the same
  change that adds the file; the oracle self-tests fail on an unlisted file or one over 200 KB.

### `syntax/`: generated syntax-layer fixtures

Healthy files of every cross-reference kind and broken files for every repair case of the M1
store (ISO 32000-2 §7.5). They are generated by `folioxide_testkit::fixtures::syntax` with
`folioxide_testkit::builder::PdfBuilder`, byte for byte and deterministically (fixed `/ID`, fixed
Flate level), and committed so tests and oracles can read them without running the generators.

- `cargo xtask fixtures` rewrites the files and the table below; never edit either by hand.
- `cargo xtask fixtures --check` (and the `committed_fixtures_are_up_to_date` test of `xtask`)
  fails when the committed files differ from the generators.
- A dependency update that changes Flate output (`miniz_oxide`) changes the compressed fixtures;
  regenerate them in the same change.
- Each row ends with the page count and two flags from `FixtureInfo`. "Not conforming" files are
  deliberately broken (or, for `encrypted*`, use fake encryption), so a conforming reader cannot
  open them without repair. "Oracle-clean" files open in pikepdf/qpdf and poppler without errors
  or warnings, so the oracle suite can check them.
- The 2,000-page laziness file is generated at test time (`fixtures::syntax::lazy_pages`) and not
  committed.

### `qpdf/`: linearized files written by qpdf

Layouts that real writers produce and `PdfBuilder` does not: qpdf's linearization (ISO 32000-2
Annex F), with the first-page cross-reference section near the start of the file and the main
section at the end. `tools/fixtures/qpdf.py` builds a three-page document with pikepdf and
saves it with libqpdf (`linearize=True`, deterministic `/ID`); the tests read them through
`folioxide_testkit::fixtures::qpdf`, and the oracle suite `syntax` checks them as cases
`qpdf-<name>`.

- Regenerate with `.venv/bin/python -I tools/fixtures/qpdf.py` (oracle venv,
  `bash tools/setup-venv.sh`); `cargo xtask fixtures` runs it too when the venv exists.
  `--check` (run by `cargo xtask fixtures --check` with the venv, and by the oracle self-tests
  in CI) regenerates them in memory and compares the bytes, and checks the linearization with
  qpdf. qpdf's output
  depends on its version, so both need the pinned pikepdf 10.16.0 with libqpdf 12.4.2; when the
  pins in `tools/requirements-dev.txt` change, regenerate these files in the same change.

### `hostile/`: generated resource-exhaustion seeds

Small instances of every resource-exhaustion shape in `folioxide_testkit::fixtures::hostile`
(`hostile::seeds()`): `/Prev` chains of cross-reference streams, overlapping sections, outsized
`/Index` arrays, object-stream bombs, object-stream headers with thousands of members, a huge
array in an object stream, unterminated trailers. Each one is also a readable one-page
document. They are committed so the fuzz corpora start from them: the nightly fuzz workflow
seeds every target with the `*.pdf` files under `fixtures/` (see `fuzz/README.md`). The
`no_panic_on_mutated_input` test mutates the same seeds, and
`crates/folioxide-syntax/tests/hostile_default_limits.rs` scales the generators up to sizes
that are generated at test time and never committed.

- `cargo xtask fixtures` rewrites the files and the table below, like `syntax/`; `--check` fails
  when they differ from the generators.
