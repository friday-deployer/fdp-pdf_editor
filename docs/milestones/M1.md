# M1 brief: syntax layer, read path

This brief is the source of truth for M1. It refines `docs/ROADMAP.md` § M1. Design reference: `docs/ARCHITECTURE.md` §A.3 (data model),
§A.4 (layering, API style, `ErrorCode`), §A.9 (testing) and §A.10 (spec traps #1–#6).

- **Goal:** `folioxide-syntax` opens any reasonable PDF **lazily and robustly**, resolves any object, decodes stream data, and serializes objects.
- **Out of scope:**
  - Document-level writing (M2)
  - The edit API (`set`/`get_mut`/`add`/`free`, M2)
  - Encryption (M5): a trailer with `/Encrypt` makes `Store::open` fail with `ErrorCode::PasswordRequired` if the trailer is otherwise valid, and `Unsupported` if the handler is not `/Standard`
  - The page tree (M2)

## How the work is staged
Developers work in **isolated git worktrees**. When each stage ends, the manager merges the branches.

| Stage | Dev A | Dev B |
|---|---|---|
| 1 (parallel) | **WP1.1** objects, lexer, parser, serializer, errors, limits, diagnostics | **WP1.2** filters |
| 2 (parallel, on top of stage 1) | **WP1.3** xref, object streams, store, repair | **WP1.4** testkit, generated fixtures, property tests, fuzz targets |
| 3 (single developer, main tree) | — | **WP1.5** integration and acceptance tests, `fuzz_parse_document`, oracle suite `syntax` |

## API contracts
Names are binding; add more API freely.

### WP1.1: objects and errors (`folioxide_syntax::…`)
- **Data model:** `ObjectId { num: u32, gen: u16 }`, `Object`, `PdfString { bytes, hex }`, `Name`, `Dict` (an `IndexMap` wrapper), `Stream { dict, data: StreamData }` and `StreamData::{Source(Range<u64>), Encoded(Vec<u8>), Decoded(Vec<u8>)}`, exactly as in §A.3.
  - Convenience accessors: `Object::as_int/as_f64/as_name/as_dict/as_array/as_ref/as_bool/as_str_bytes`, `Dict::get(&[u8])`, `Dict::insert`, typed getters.
- **Errors:** `ErrorCode` (the full list from §A.4, `#[non_exhaustive]`, with an optional serde derive behind the crate feature `serde`), `Error` (thiserror) with `code()`, and `type Result<T> = std::result::Result<T, Error>`.
  - Errors carry a byte offset where meaningful.
- **Limits and policy:** `Limits` with the defaults from §A.3, `Diagnostic { offset: Option<u64>, kind: DiagnosticKind, message: String }`, and `Strictness::{Lenient, Strict}`.
- **Lexer:** `Lexer::new(&[u8], start: usize)` produces tokens with positions. It covers every case in §7.2–7.3 and trap #2.
- **Parser:**
  - `parse_object(bytes, pos, &ParseCtx) -> Result<(Object, usize)>` for direct objects, with a depth limit.
  - `parse_indirect_at(bytes, offset, &ParseCtx, length_resolver: &dyn Fn(ObjectId) -> Option<i64>) -> Result<IndirectObject { id, object, stream_data_range: Option<Range<u64>>, end }>`.
  - The stream data range comes from `/Length` (direct, or indirect via the resolver).
  - **Recovery:** if `endstream` does not follow at `start+Length` (after an optional EOL), scan forward for `endstream` and emit a `Diagnostic`.
  - A missing `endobj` is tolerated.
- **Serializer:** `serialize_object(&Object, &mut Vec<u8>)`, plus `serialize_indirect(id, &Object, encoded_stream_bytes: Option<&[u8]>, &mut Vec<u8>)`.
  - Reals: no exponent, at most 10 fractional digits, trailing zeros trimmed, `-0` written as `0`; integral reals keep a `.0`, or an equivalent that round-trips as Real.
  - Names are escaped per §7.3.5. Strings are written literal or hex according to `PdfString::hex`, with literal escaping (parens, backslash, CR/LF) per §7.3.4.2.

### WP1.2: filters (`folioxide_syntax::filters`); must not depend on WP1.1 types
- **Filter enum:** `Filter::{Flate, Lzw, AsciiHex, Ascii85, RunLength, Dct, Jpx, Jbig2, CcittFax, Crypt}`.
  - `Filter::from_name(&[u8]) -> Option<Filter>` also accepts the inline-image abbreviations `AHx`, `A85`, `LZW`, `Fl`, `RL`, `CCF`, `DCT`.
  - `Filter::is_passthrough()` is true for DCT, JPX, JBIG2 and CCITT.
- **Parameters:** `FilterParams { predictor: u8, colors: u8, bits_per_component: u8, columns: u32, early_change: bool }` with spec defaults. Limits come from a `DecodeLimits { max_output: usize }` struct.
- **Decoding:**
  - `decode(filter, &[u8], &FilterParams, &DecodeLimits) -> Result<Decoded, FilterError>`, where `Decoded { data: Vec<u8>, truncated: bool }`.
  - Truncated or corrupt Flate input returns what could be decoded, with `truncated: true`.
- **Chains:** `decode_chain(&[(Filter, FilterParams)], data, &DecodeLimits) -> Result<ChainOutput { data, remaining: Vec<Filter>, truncated }, FilterError>`. It stops at the first passthrough filter and returns the filters that remain.
- **Encoders:** `encode_flate(&[u8], level: u8)`, `encode_ascii_hex`, `encode_ascii85`.
- **Predictors:** TIFF predictor 2 and the PNG predictors 10–15, decode side, with `checked_mul` overflow checks.
- **Errors:** `FilterError` (thiserror) with variants `Corrupt { filter, detail }`, `LimitExceeded { limit: usize }`, `Unsupported { filter }` and `InvalidParams { detail }`. WP1.3 maps them to `ErrorCode::{Filter, LimitExceeded, Unsupported}`.

### WP1.3: store (`folioxide_syntax::store`, re-exported at the crate root)
- **Opening:**
  - `pub type SharedBytes = Arc<dyn AsRef<[u8]> + Send + Sync>;` and `impl From<Vec<u8>>`-style helpers (e.g. `Store::open_bytes(Vec<u8>, &OpenOptions)`).
  - `OpenOptions { strictness, limits }` is `#[non_exhaustive]`, has `Default` and `with_*` setters. A password field arrives in M5.
  - `Store::open(SharedBytes, &OpenOptions) -> Result<Store>`.
- **Resolving:** `resolve(&self, ObjectId) -> Result<Arc<Object>>`. A free or missing object gives `Object::Null`. A wrong generation gives `Null` plus a diagnostic. Reference chains are followed only with `deref(&Object)`.
- **Stream data:**
  - `stream_data(&self, &Stream) -> Result<StreamBytes>` decodes through the filter chain. It returns decoded bytes plus the remaining passthrough filters and a truncated flag, and enforces `max_decoded_stream` and `max_total_decoded`.
  - `raw_stream_data(&self, &Stream) -> Result<Cow<[u8]>>`.
- **Introspection:**
  - `trailer(&self) -> &Dict` (the newest trailer) and `revisions(&self) -> &[Revision]`, where `Revision` is as in §A.3.
  - `header_offset()`, `version() -> (u8, u8)` (header, overridable by the catalog `/Version`, which is the model's job and not this one's), `object_ids(&self) -> Vec<ObjectId>` (in-use per the merged xref), `max_object_number()`.
  - `diagnostics(&self) -> Vec<Diagnostic>`.
- **Laziness:** `#[doc(hidden)] pub fn parsed_object_count(&self) -> usize` (used by `open_is_lazy`).
- **Threading:** `Store: Send + Sync`, asserted in a test.
- **Xref coverage:**
  - Tables with EOL variants, subsections, and an off-by-one first subsection.
  - Xref streams with `/W` (zero-width fields take their defaults), `/Index`, and `/Prev`.
  - Hybrid files with `/XRefStm`.
  - `/Prev` chains with loop detection and `max_xref_sections`.
  - Header offset (junk before `%PDF-`).
  - **Offset validation:** check that `N G obj` exists at the offset, then search ±64 bytes, then fall back to full reconstruction (`repair.rs`): scan for `N G obj` and `trailer`, and rebuild the trailer when it is missing by finding the `/Type /Catalog` object.
- **Object streams:** validate `/N`, `/First` and the offsets; handle `/Extends` chains with loop detection; objects inside are gen 0; cache decoded containers (`OnceLock`).

### WP1.4: testkit (`folioxide_testkit`)
- **Builder:** `PdfBuilder` is a byte-level builder.
  - `header(version)`, `junk_prefix(bytes)`, `obj(num, gen, body: &str or bytes)`, `stream_obj(num, gen, dict, data, length_override: Option<LengthSpec>)`, `raw(bytes)`.
  - Xref output: `xref_table(XrefOpts { eol_variant, first_subsection_start, offset_skew, … })`, `xref_stream(…)`, `trailer(dict)`, `startxref(Some(offset_override))`, `eof()`, and `build() -> Vec<u8>`.
  - It records true offsets so deliberately wrong offsets can be produced.
- **Generators:** `fixtures::syntax::all() -> Vec<(&'static str, Vec<u8>)>` produces at least the cases below. Each committed file is under 200 KB; the 2,000-page lazy case is generated at test time and **not** committed.
  - minimal, multi-revision, xref-stream, hybrid, objstm, objstm-extends
  - every broken case named in the acceptance criteria
  - a 2,000-page file for the laziness test
- **Committing fixtures:** `cargo xtask fixtures` writes them to `fixtures/syntax/` deterministically, and `cargo xtask fixtures --check` fails if the committed files differ from the generated ones.
- **Property tests:**
  - `proptest_object_roundtrip` (≥10k cases): any `Object` tree within limits serializes and parses back equal. Reals are compared after serializer rounding.
  - The `emit` feature writes oracle cases (used by WP1.5).
- **Fuzzing:** targets `fuzz_lexer` and `fuzz_filters`.

### WP1.5: integration (main tree, after the stage-2 merge)
- **Integration tests** in `crates/folioxide-syntax/tests/` cover every acceptance test name that is not already a unit test, using testkit fixtures.
- **`no_panic_on_mutated_input`:** at least 20k mutations across all fixtures. Mutations are byte flips, truncations, insertions and chunk duplication, seeded and deterministic. Run `Store::open` on each, then resolve every object and decode every stream, with no panic.
- **`open_is_lazy`:** open the generated 2,000-page file and resolve the root, parsing fewer than 50 objects.
- **Fuzzing:** target `fuzz_parse_document`.
- **Oracle suite `syntax`:**
  - The tests emit each `fixtures/syntax` case plus `expect.json` with `objectCount` (our reachable in-use count) and `pages` where applicable.
  - Add an `objectCount` check to `run_suite.py`, using pikepdf `len(pdf.objects)` adjusted per the rules you document.
  - Restrict the suite to fixtures that pikepdf/qpdf open without repair; mark repaired cases `"oracleSkip": "reason"`.

## Acceptance criteria (QA verifies each one)
1. **Gates:** `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`, `cargo deny check` and `cargo xtask ci` all pass.
2. **Named tests:** `cargo test -p folioxide-syntax` contains and passes, as unit or integration tests:
   - lexer, serializer and parser: `lexer_spec_examples`, `real_formatting_no_exponent`, `name_escape_roundtrip`, `depth_limit_errors_not_overflow` (100k nested `[` gives an error, not a stack overflow)
   - filters: `flate_truncated_partial`, `flate_bomb_limited`, `png_predictor_all_types`, `lzw_early_change`, `ascii85_z_and_eod`
   - xref repair: `xref_table_eol_variants`, `xref_subsection_starts_at_1_repaired`, `startxref_off_by_n_repaired`, `prev_loop_detected`, `junk_before_header`
   - xref streams and object streams: `xref_stream_w0_default`, `hybrid_xrefstm`, `objstm_extends_chain`
   - stream length and reconstruction: `stream_length_wrong_recovers`, `length_indirect_cycle`, `missing_xref_full_reconstruct`
   - encryption detection: `encrypted_returns_password_required`
3. **Laziness:** `open_is_lazy` passes (fewer than 50 objects parsed).
4. **Property tests:** `proptest_object_roundtrip` runs at least 10k cases, and `no_panic_on_mutated_input` runs at least 20k mutations; both pass. Run them in release mode if debug is too slow, and document that.
5. **Fuzz targets:** `cargo +nightly fuzz build` (in `fuzz/`) builds `fuzz_lexer`, `fuzz_filters` and `fuzz_parse_document`. A local smoke run of 60 s per target finds no crash.
6. **Fixtures:** `cargo xtask fixtures --check` passes (committed fixtures are reproducible), and `fixtures/README.md` lists them.
7. **Oracle:** `cargo xtask oracle --suite syntax` exits 0, with at least 6 cases checked rather than skipped.
8. **Robustness:**
   - No `unwrap`/`expect`/`panic!`/unchecked indexing in non-test code (clippy lints enforce this).
   - Every recursion is depth-limited.
   - Every allocation sized from file data is bounded by `Limits`.
9. **Docs and threading:** all public items have rustdoc (`missing_docs` is clean), and `Store: Send + Sync` is asserted.
