# M3 brief: Signatures I. PAdES B-B, external two-phase signing, sequential signatures, verification

This brief is the source of truth for M3. It refines `docs/ROADMAP.md` § M3.
- **Design references:**
  - `docs/ARCHITECTURE.md` §A.3: Store, Revision, `structure_repaired`, `recovered_objects`, `offset_base`; incremental save
  - §A.4: errors
  - §A.6: signature design. This brief **supersedes** A.6.2 sizing, the A.6.5 contracts and the A.6.7 enums where it differs; the manager updates A.6 after M3.
  - §A.7: Node
  - §A.9: oracles
  - §A.10: traps #12, #13, #14
- **Decisions that apply:** `docs/DECISIONS.md` D5.4 (RSA advisory), D7.5/D7.6 (oracle conventions), D9.4 and D9.8 (repaired structure ⇒ full save; qpdf reference reader).
- **Binding contracts from M2:** `docs/milestones/M2.md`.

- **Goal:**
  - Invisible PAdES B-B signatures (`/SubFilter /ETSI.CAdES.detached`) with local keys (PKCS#12, PEM) and with an external two-phase flow (HSM, KMS, WebCrypto, `node:crypto`).
  - Sequential signatures, each in its own incremental update, that keep earlier signatures valid and classified by pyHanko as `FORM_FILLING`.
  - A verifier that reports integrity, cryptographic validity, ByteRange sanity, coverage, a basic modification level, certificate info and an optional trust result, with explicit defences against the published PDF-signature attack classes.
- **Out of scope:**
  - RFC 3161 signature timestamps (B-T) and document timestamps (M4). `/DocTimeStamp` dictionaries are *listed* by `verify` but not verified.
  - DocMDP certification, the full DocMDP/FieldMDP modification policy, and visible appearances (M4). M3 still *reads* `/Perms /DocMDP` to refuse signing a P=1 document (R-14).
  - Encrypted documents (M5). They do not open in M3 (`PasswordRequired`), so neither sign nor verify reaches them.
  - LTV, `/DSS` and B-LT/B-LTA (M11). FieldMDP `/Lock` (M11).
  - Creating RSA-PSS signatures (verification only), P-521, Ed25519.

## 0. Reference behaviour (agree with this before writing code)
Lesson from M1 (team.md): every behaviour that can produce a reader differential needs a reference fixed up front.

- **Reference validator:** **pyHanko 0.37.0** (`validate_pdf_signature` with `strict=False`, no fetching, `fixtures/pki/root.pem` as the trust root).
- **Secondary oracles:** `openssl cms -verify` (via `extract_cms.py`) and poppler `pdfsig -nocert`. They must agree with pyHanko on *intact ∧ valid* (existing runner semantics, D7.6).
- **Reference for "what the file means":** qpdf, as in D9.8.

I read the pyHanko 0.37.0 sources in `.venv` (`sign/validation/pdf_embedded.py`, `generic_cms.py`, `status.py`, `sign/diff_analysis/**`, `sign/fields.py`). I also ran probes in my scratchpad: pyHanko-signed files, then ISA, relist, repoint, free and trailing-data variants. The table below is grounded in those runs.

| Report field | pyHanko quantity | Rule |
|---|---|---|
| `intact` | `status.intact`: digest over the ByteRange *as written* (any even number of pairs) equals `message-digest`. With no signedAttrs, `intact = valid` | **Agree exactly** whenever pyHanko produces a status. Ours is `false` when the ranges are not computable (negative values, odd count, past EOF); pyHanko then raises or reports a mismatch. |
| `signature_valid` | `status.valid`: signature over the **original** signedAttrs bytes re-tagged `0x31` (asn1crypto keeps the original encoding; it never re-sorts) | **Agree.** We also verify the original bytes and never re-encode. **Deliberate differences:** (a) algorithms we do not implement (P-521, Ed25519, DSA, MD5) give `false` plus `UnsupportedAlgorithm`; (b) a `signatureAlgorithm` whose hash differs from `digestAlgorithm` gives `false` (pyHanko: valid, but trust problem). |
| ESS signing-certificate(-v2) mismatch, content-type missing or ≠ eContentType, more than one SignerInfo, eContent present on a detached SubFilter, CMSAlgorithmProtection mismatch | pyHanko raises `SignatureValidationError` / `CMSExtractionError` (no status, so "not valid") | Ours: `signature_valid=false` plus a typed problem. **Agree on "not valid".** |
| `trusted` | path to the anchors, signer KU must contain **nonRepudiation** (`PdfSignatureStatus.key_usage = {'non_repudiation'}`), validity at *now* (no timestamp), weak hashes (`md2`, `md5`, `sha1`) make it untrusted | **Agree** given the same anchors and validation time (Node passes `Date.now()`). **Deliberate difference:** we accept KU digitalSignature **or** nonRepudiation (Adobe and EU DSS behaviour). Fixtures have both bits, so no oracle case diverges. |
| `coverage` | `ENTIRE_FILE`: `len1+len2+2·len(Contents)+2 == file size`. `ENTIRE_REVISION`: contiguous gap, `startxref` before `b+c` names the signed revision, and every xref section up to it ends ≤ `b+c`. `CONTIGUOUS_BLOCK_FROM_START`, `UNCLEAR` | **Agree exactly** (same 4-way enum, §5 V5). |
| `modification` | `NONE`, `LTA_UPDATES`, `FORM_FILLING`, `ANNOTATIONS`, `OTHER` (`DEFAULT_DIFF_POLICY`) | **Never more lenient than pyHanko.** **Equal** for: nothing appended (`None`); our own sequential signature (`FormFilling`); `/Info`-only update or an identical re-listing (`LtaUpdates`, probe `C_relist` gave `LTA_UPDATES`); freeing, content, page, font or catalog changes (`Other`, probes `B_isa` and `F_free` gave `OTHER`). **Stricter** (ours `Other`): (1) bytes or objects after the last revision that no `startxref` reaches (probe `A_noxref`: pyHanko `NONE`; ours `Other` via `UnreferencedUpdate`, D9.8); (2) generic form-field value changes (pyHanko `FORM_FILLING`; ours `Other` until M4 WP4.2); (3) `/DSS` updates (pyHanko `LTA_UPDATES`; ours `Other` until M11); (4) any repaired structure while bytes follow the signed range. |
| pdfsig / openssl | intact ∧ valid only | Must equal `intact && signature_valid` (runner D7.6). |

**Our extra fields with no pyHanko analogue:** `byte_range_ok`, `problems`, `pades_level`.
- These must never be `true` or `B-B` where pyHanko reports `intact=False` or `valid=False`, or raises.
- **SWA case:** pyHanko gives `intact=True`, `valid=True`, `coverage=UNCLEAR`, `modification=OTHER`. Ours gives the same intact, valid and coverage, plus `byte_range_ok=false`, so `is_valid()` is false.

**Agreement by construction.** Every `sign-bb` / `sign-attacks` case writes its expect.json `signatures[]` values (`intact`, `valid`, `trusted`, `coverage`, `modification`) **from Folioxide's own `SignatureReport`**. The oracle run is therefore a pyHanko/pdfsig/openssl-vs-Folioxide differential. Deliberate differences live in one table in the test code, `DELIBERATE_DIFFERENCES: &[(case, field, ours, pyhanko, reason)]`. There the expect file carries pyHanko's value and the Rust test asserts ours.

## 1. What M2 delivers, and what M3 adds below `folioxide-sign`
**From M2 (binding):**
- `Store` edit API (`set`, `get_mut`, `add`, `free`, `set_trailer_entry`, `is_modified`, `edited_ids`, `generation_of`)
- `writer::save_incremental` / `incremental_suffix` with `IncrementalOptions { deterministic, id1 }`
- **Incremental save follows the previous xref kind:** a table after a table, a stream after a stream or hybrid.
- **Incremental save never compresses:** no object streams in increments.
- **Offsets follow `offset_base()`.**
- **Refusals:** an incremental save is refused for `XrefKind::Reconstructed` or `structure_repaired()` (`Unsupported`), and for no source (`InvalidArgument`).
- **Document facade:** `Document::{open, open_shared, from_store, store, store_mut, catalog, page_count, page_ids, page}`.
- **Model types:** `PdfDate` (`parse`, `to_pdf_string`, `to_rfc3339`) and `text::{encode,decode}_text_string`.

**M3 additions to `folioxide-syntax`** (Dev A, stage 1, in `crates/folioxide-syntax/src/{writer/**, store.rs}`; additive only):
```rust
/// Absolute byte layout of an incremental update produced with an overlay.
#[non_exhaustive] pub struct IncrementalLayout {
    pub suffix: Vec<u8>,                       // bytes appended to the source (leading EOL included)
    pub base: u64,                             // absolute offset of suffix[0] in the output (= source.len())
    pub spans: Vec<(ObjectId, Range<u64>)>,    // ABSOLUTE span of every object written: "N G obj" .. after "endobj\n"
}
/// Like incremental_suffix, but `overlay` objects are written as if they were edits (they win over
/// store edits with the same id) WITHOUT mutating the store. Overlay ids are either in use (replace)
/// or >= store.next_object_number() (new). Overlay objects are never compressed or put in an ObjStm.
pub fn incremental_suffix_with_overlay(store: &Store, opts: &IncrementalOptions,
        overlay: &BTreeMap<ObjectId, Object>) -> Result<IncrementalLayout>;
impl Store {
    /// Smallest object number above every number any xref section lists (free entries included) and
    /// every edited/added id. New objects never reuse a freed number (pyHanko's `is_ref_unassignable`
    /// treats reuse as clobbering, so a sequential signature would become OTHER).
    pub fn next_object_number(&self) -> u32;
    /// Where an object's current definition lives: InFile { start, end } (absolute; start = "N G obj",
    /// end = after the parse that produced the resolved object, i.e. after "endobj"), or
    /// InObjStm { stream, index }; None for free/missing. Edited objects report their source location.
    pub fn object_location(&self, id: ObjectId) -> Option<ObjectLocation>;
}
```
- **Serializer contract** (already true in M1; now pinned by a test):
  - hex strings are written `<HEX…>` in uppercase with **no whitespace**, whatever their length
  - arrays are written `[a b c]` with single spaces
- **Why it matters:** pyHanko's ENTIRE_FILE formula assumes 2 hex digits per byte (`contents_hex_no_whitespace`).

### 3.1 Dev B: PDF-agnostic crypto (`folioxide_sign::{algorithms, keys, signer, cms, x509info}`)
```rust
// algorithms.rs
#[non_exhaustive] #[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub enum DigestAlgorithm { Sha256, Sha384, Sha512, /** verification only */ Sha1 }
impl DigestAlgorithm {
    pub fn output_len(self) -> usize;
    pub fn hasher(self) -> Hasher;                 // streaming: update(&[u8]), finalize() -> Vec<u8>
    pub fn digest(self, parts: &[&[u8]]) -> Vec<u8>;
}
#[non_exhaustive] #[derive(Clone, Copy, Debug, PartialEq, Eq, Hash)]
pub enum SignatureAlgorithm { RsaPkcs1v15, Ecdsa }  // curve comes from the certificate; RSA-PSS is verify-only (internal)
#[non_exhaustive] #[derive(Clone, Copy, Debug, PartialEq, Eq)]
pub enum KeyKind { Rsa { bits: u32 }, EcP256, EcP384 }
/// Allowed signing combinations: RSA (>= 2048 bits) x {256,384,512}; P-256 x {256,384,512}; P-384 x {256,384,512}.
/// Defaults: RSA -> Sha256, P-256 -> Sha256, P-384 -> Sha384. Sha1 is never allowed for signing (InvalidArgument).
pub fn default_digest(kind: KeyKind) -> DigestAlgorithm;

// signer.rs
pub trait Signer: Send + Sync {
    /// DER certificates, signer first, then intermediates (root optional). Never re-encoded.
    fn certificate_chain(&self) -> &[Vec<u8>];
    fn algorithm(&self) -> SignatureAlgorithm;
    fn key_kind(&self) -> KeyKind;
    /// Signs `to_be_signed` (hashing it with `digest`). RSA: exactly modulus-length bytes.
    /// ECDSA: DER ECDSA-Sig-Value or IEEE P1363 r||s (both accepted downstream).
    fn sign(&self, digest: DigestAlgorithm, to_be_signed: &[u8]) -> Result<Vec<u8>>;
}
pub struct LocalSigner { /* Zeroizing key material; Debug prints only the key kind and the subject */ }
impl LocalSigner {
    pub fn from_pkcs12(p12_der: &[u8], password: &str) -> Result<LocalSigner>;
    pub fn from_pem(key_pem: &str, certs_pem: &str, key_password: Option<&str>) -> Result<LocalSigner>;
    pub fn from_pkcs8_der(key_der: &[u8], chain_der: Vec<Vec<u8>>) -> Result<LocalSigner>;
    /// RNG used for RSA blinding (see R-9). Default: getrandom SysRng behind feature `sys-rng` (default on).
    pub fn with_rng(self, rng: Box<dyn rand_core::CryptoRng + Send>) -> Self;
}
impl Signer for LocalSigner { .. }
```
- **`LocalSigner` construction rules:**
  - The key must match `chain[0]`'s SPKI, else `KeyLoad`. For PEM the chain is **reordered** so that the certificate matching the key comes first; the other certificates keep their order.
  - RSA keys below 2048 bits or above 8192 bits give `KeyLoad`. Unsupported curves give `Unsupported`.
- **RSA signing** uses `rsa::pkcs1v15::SigningKey::<D>` through **`RandomizedSigner::try_sign_with_rng`**. Verified in rc.19 `src/pkcs1v15/signing_key.rs`: the plain `Signer::try_sign` path calls `sign::<DummyRng>(None, …)` and is therefore **unblinded**; only the `_with_rng` path blinds (`rsa_decrypt_and_check(priv, Some(rng), …)`). The output is identical, since PKCS#1 v1.5 is deterministic.
- **ECDSA signing** uses `ecdsa::SigningKey` through `signature::Signer` (RFC 6979 deterministic; ecdsa 0.17 `signing.rs` `sign_prehashed_rfc6979`), so outputs are reproducible for `external_two_phase_matches_local`. With a non-default digest it uses `PrehashSigner::sign_prehash(H(tbs))`.
- **Key loading** (verified against `p12-keystore 0.4.0` and `pkcs8 0.11.0` sources):
  - PKCS#12: `p12_keystore::KeyStore::from_pkcs12(data, password, Pkcs12ImportPolicy::Strict)`, then `.private_key_chain()` → `(alias, &PrivateKeyChain)`. `chain.key().as_der()` is PKCS#8 DER; `chain.certs()` are leaf-first, `Certificate::as_der()`.
  - The MAC is verified **before** any decryption (`Pkcs12Archive::from_pkcs12` → `codec::verify_mac`).
  - **Error mapping:**
    - `p12_keystore::Error::MacError` → `WrongPassword`. So do `Pkcs5Error`/`UnpadError` when the file has no MAC.
    - `UnsupportedEncryptionScheme`/`UnsupportedMacAlgorithm`, or RC2/3DES without feature `pkcs12-legacy` → `Unsupported`.
    - Everything else, and "no private key" or "no certificate for the key" → `KeyLoad`.
  - PEM:
    - `BEGIN PRIVATE KEY` is PKCS#8.
    - `BEGIN ENCRYPTED PRIVATE KEY` is PKCS#8 PBES2: `EncryptedPrivateKeyInfoRef::decrypt(password)`. A decrypt or padding failure, or decrypted bytes that do not parse, give `WrongPassword`. No password gives `PasswordRequired`.
    - `BEGIN RSA PRIVATE KEY` is PKCS#1. `BEGIN EC PRIVATE KEY` is SEC1.
    - Legacy OpenSSL `Proc-Type: 4,ENCRYPTED` gives `Unsupported`.
    - `certs_pem` holds one or more `BEGIN CERTIFICATE` blocks.
  - **Hygiene:**
    - Error messages never contain passwords or key bytes (test `error_messages_never_contain_password`).
    - Decrypted key buffers are `Zeroizing`.
    - Note: `p12_keystore::PrivateKey` keeps a non-zeroized copy until dropped. That is accepted and documented.

## 4. Byte-level and CMS-level specification

### 4.1 The incremental update (refines A.6.1)
```
<source bytes [0, L) untouched, junk-free (header_offset must be 0, R-5)>
[\n]                                   only if source[L-1] ∉ {CR, LF}   (M2 rule)
<pending doc edits, in id order>       same revision as the signature (A.6.1)
W 0 obj  <</Type /Annot /Subtype /Widget /FT /Sig /T (Signature1) /V S 0 R /F 132 /Rect [0 0 0 0] /P P 0 R>>  endobj
S 0 obj  <</Type /Sig /Filter /Adobe.PPKLite /SubFilter /ETSI.CAdES.detached /M (D:20261010120000Z)
          [/Name (…)] [/Reason (…)] [/Location (…)] [/ContactInfo (…)]
          /ByteRange [0 9999999999 9999999999 9999999999] /Contents <0000…0000>>>  endobj
P 0 obj  (page dict + /Annots [… W 0 R])  — or the indirect /Annots array object
A 0 obj  (AcroForm: /Fields [… W 0 R], /SigFlags 3 per §4.5)  — or the indirect /Fields array; or a NEW AcroForm + catalog edit
xref … trailer <</Size …/Prev …/Root …/Info …/ID [<orig0> <new1>]>>   (or an xref stream; same kind as the last revision)
startxref
<offset>
%%EOF\n
```
- **Object-number order:** whatever the writer does (id order). `S` and `W` are new numbers ≥ `next_object_number()`, never reused freed numbers.
- **The sig dict and the widget are never compressed.** This follows from M2's "no object streams in increments" plus the overlay contract; tested on the `objstm` and `xref-stream` fixtures.
- **Key order in the sig dict is fixed:** `/ByteRange` comes **before** `/Contents`, so the ByteRange lies in signed part 1, and `/Contents` is the last key. The verifier must not depend on this (pyHanko writes `/Contents` first).
- **Field/widget dictionary** (ISO 32000-2 §12.7.5.5 signature fields and §12.5.6.19 widget annotations; 32000-1 §12.7.4.5):
  - merged field and widget; `/FT /Sig`
  - `/T`: the partial name (no `.`, §12.7.4.2), encoded with `encode_text_string`
  - `/V`: an **indirect** reference to the new sig dict (pyHanko requires an indirect, newly created `/V`)
  - `/F 132` = Print (bit 3) | Locked (bit 8), §12.5.3 Table 167
  - `/Rect [0 0 0 0]`: zero-area, so **no `/AP`** is needed. In PDF 2.0 Table 166, `/AP` is not required for annotations with a zero-width or zero-height `/Rect`; verify the wording in your copy.
  - `/P`: the page
  - The widget is added to that page's `/Annots`.
  - **The new field goes at the root of `/AcroForm /Fields`**, never under `/Kids`. pyHanko's `SigFieldCreationRule` only allows root-level sig-field creation.
- **AcroForm** (§12.7.3, Table 224; SigFlags Table 225; 32000-1 Tables 218/219): see §4.5 for when `/SigFlags 3` (SignaturesExist | AppendOnly) is written.
- **`/M`** is `PdfDate::to_pdf_string()` of `signing_time` (§7.9.4). It is **required by PAdES B-B** (Table 1 row "M", cardinality 1; see §4.6). There is no CMS signing-time.
- **`/Name`, `/Reason`, `/Location`, `/ContactInfo`** are text strings (`encode_text_string`; UTF-16BE BOM when needed).
  - `/Reason` must not be combined with a commitment-type-indication or signature-policy attribute (EN 319 142-1 §6.3 add. req. (d)/(m)). We emit neither attribute, so `/Reason` is always allowed.
- **Never written:** `/Cert` (cardinality 0 in PAdES B-B), `/Prop_Build`, `/Reference` (M4).

### 4.2 `/ByteRange`, `/Contents`, digest, sizing (refines A.6.2)
1. **Exact size first.**
   - `signed_attrs = build_signed_attrs({digest, document_digest: [0; len], signer_cert})`. The length is independent of the digest value.
   - `needed = cms_len_upper_bound(signed_attrs, chain, alg, kind, digest)`.
   - `R = contents_reserve.unwrap_or(max(8192, round_up_1024(needed + 512)))`. In M4 `tsa_reserve` is added to the default.
   - If an explicit `contents_reserve < needed`, `prepare` fails with `PlaceholderTooSmall { needed, reserved }` **before** anything is signed. `sign()` then retries once with `needed`.
   - `R > 4 MiB` gives `InvalidArgument`.
2. **Serialize the update** via `incremental_suffix_with_overlay`. The sig dict carries `Object::Array([Int(0), Int(9_999_999_999) ×3])` and `PdfString::new_hex(vec![0; R])`, so the serializer emits `[0 9999999999 9999999999 9999999999]` and `<` + `2R` × `0` + `>`.
3. **Locate both tokens** inside `spans[S]` with the M1 `Lexer`: the dict at depth 1, key `/ByteRange` then its array token, key `/Contents` then its hex-string token.
   - `a` = absolute offset of `<`; `b` = offset just after `>`; `c = total_len − b`.
   - Require `b − a == 2R + 2`.
4. **Patch the ByteRange in place:**
   - Write `[0 a b c` (plain decimal, **no leading zeros**), then spaces up to the placeholder length, then `]`. The total width never changes.
   - `a`, `b` and `c` must each fit in 10 digits, else `InvalidArgument` ("file too large for the ByteRange placeholder", ≥ 9,999,999,999 bytes).
   - ByteRange values are **file-absolute** (§12.8.1). Junk before the header is refused (R-5).
5. **Digest:** `document_digest = H(out[0..a] ‖ out[b..b+c])`, streamed (the source, then the suffix pieces). §12.8.1: the range covers the entire file except the `/Contents` value, delimiters included.
6. **To be signed:** `signed_attrs` is rebuilt with the real digest.
7. **Embedding:**
   - `hex = UPPER(cms)`, written at `a+1`; the remaining `2R − 2·len(cms)` digits stay `0`.
   - DER length self-delimits. Verifiers read the outer DER length; pyHanko and `extract_cms.py` require only zero padding.
   - `/Contents` keeps exactly `2R` hex digits, with no whitespace (pyHanko's ENTIRE_FILE formula uses `2·len(Contents)+2`).

### 4.3 CMS (RFC 5652, CAdES/PAdES baseline)
```
ContentInfo ::= SEQ { contentType id-signedData (1.2.840.113549.1.7.2), [0] EXPLICIT SignedData }
SignedData  ::= SEQ { version 1, digestAlgorithms SET { AlgId(digest, params ABSENT) },
                      encapContentInfo SEQ { eContentType id-data (1.2.840.113549.1.7.1) }   -- eContent ABSENT (detached)
                      certificates [0] IMPLICIT SET OF  -- the INPUT DER of every chain cert, byte-identical, DER-sorted
                      -- no crls
                      signerInfos SET { SignerInfo } }
SignerInfo  ::= SEQ { version 1, sid IssuerAndSerialNumber { issuer = RAW issuer Name bytes from the cert TBS,
                      serialNumber = RAW INTEGER from the cert }, digestAlgorithm AlgId(digest, ABSENT),
                      signedAttrs [0] IMPLICIT SET OF Attribute  -- same content octets as the 0x31 TBS
                      signatureAlgorithm, signature OCTET STRING }   -- no unsignedAttrs in M3
```
- **The whole SignedData is DER.** EN 319 142-1 requires "a DER-encoded SignedData object as specified in EN 319 122-1" (quoted in EU DSS `CMSForPAdESBaselineRequirementsChecker`; see §9).
- **Certificates are never re-encoded.** Re-encoding a non-canonical certificate breaks its own signature; copying `issuer`/`serial` from a re-encoded `Name` can break `sid` matching. Raw slices come from our TLV walker.
- **SET OF ordering** is DER (X.690 §11.6): sort the encodings.
  - `der::SetOfVec::try_from(Vec)` sorts (der 0.8.2 `set_of.rs` `der_sort`, `sort_unstable_by(der_cmp)`).
  - **Do not hand-order the attributes.** The order depends on lengths. For SHA-384, message-digest (`30 3F…`) sorts *after* a short signing-certificate-v2 (`30 39…`). Test `cms_signed_attrs_der_sorted` checks every digest.
- **Signed attributes, exactly three** (pyHanko 0.37 emits the same three; confirmed by probe):
  1. `content-type` (1.2.840.113549.1.9.3) = `{ id-data }`.
  2. `message-digest` (1.2.840.113549.1.9.4) = `OCTET STRING document_digest`.
  3. `signing-certificate-v2` (1.2.840.113549.1.9.16.2.47; RFC 5035 §3) = `SigningCertificateV2 { certs SEQ { ESSCertIDv2 } }`, no `policies`.
     - `ESSCertIDv2 { hashAlgorithm AlgId DEFAULT {id-sha256}, certHash = H(signer cert DER), issuerSerial { GeneralNames { [4] directoryName issuer }, serialNumber } }`.
     - **DEFAULT omission:** with SHA-256 the `hashAlgorithm` field is **absent** (DER omits DEFAULT values; X.690 §11.5).
     - With SHA-384/512 it is present as `{oid, params ABSENT}`.
     - Implement it with der-derive `#[asn1(default = "sha256_alg_id")]`, where the default has `parameters: None`. `{sha256, NULL}` is a *different* value and would be encoded, which is a bug the test must catch.
     - certHash uses the signature's digest algorithm.
- **Never present:** `signing-time` (PAdES: cardinality 0), signing-certificate v1 (only for SHA-1, EN 319 122-1 add. req. (h)/(i)), CMSAlgorithmProtection, content-timestamp, commitment-type, signature-policy.
- **The 0x31 rule** (RFC 5652 §5.4): the signature is computed over the DER of `SET OF Attribute` with the universal SET tag `0x31`, not the `[0] IMPLICIT` tag `0xA0` used inside SignerInfo.
  - `build_signed_attrs` returns the `0x31` form.
  - `assemble` writes `0xA0` followed by **identical** length and content octets (test `cms_signed_attrs_retagged_0x31`: `si_attrs[0]==0xA0 && si_attrs[1..]==tbs[1..]`).
- **Algorithm OIDs and parameters:**
  - Digests: SHA-256 `2.16.840.1.101.3.4.2.1`, SHA-384 `…2.2`, SHA-512 `…2.3` (params **absent**, RFC 5754 §2; accept NULL on verify); SHA-1 `1.3.14.3.2.26` (verify only).
  - RSA: `sha256WithRSAEncryption` `1.2.840.113549.1.1.11`, `…1.12` (SHA-384), `…1.13` (SHA-512), params **NULL** (RFC 4055 §5). On verify also accept `rsaEncryption` `1.2.840.113549.1.1.1` (RFC 3370 §3.2), `sha1WithRSAEncryption` `…1.5`, and `RSASSA-PSS` `…1.10` with params (hash, MGF1 `…1.8` with the **same** hash, saltLength default 20, trailerField 1; a different MGF hash gives `UnsupportedAlgorithm`).
  - ECDSA: `ecdsa-with-SHA256/384/512` `1.2.840.10045.4.3.2/.3/.4`, params **absent** (RFC 5758 §3.2). On verify also accept `id-ecPublicKey` `1.2.840.10045.2.1` and `ecdsa-with-SHA1` `1.2.840.10045.4.1`.
  - Curves: `prime256v1` `1.2.840.10045.3.1.7`, `secp384r1` `1.3.132.0.34`.
- **ECDSA value:**
  - `SignatureValue` must be DER `ECDSA-Sig-Value ::= SEQ { r INTEGER, s INTEGER }` with **minimal** positive INTEGERs.
  - **Normalisation in `assemble`:**
    1. Strict DER that consumes all bytes is used, re-encoded minimally (KMS outputs with superfluous leading zeros are normalised).
    2. Otherwise, a length of exactly `2·⌈n/8⌉` (64 for P-256, 96 for P-384) is P1363 `r‖s`.
    3. Otherwise `SignatureInvalid`.
    4. `finish` then **verifies** the result. If verification fails and the bytes also admit the other interpretation, that one is tried before failing.
  - **Low-S is not required:** P-256 has `NORMALIZE_S = false` (p256 0.14.0 `src/ecdsa.rs`), and ecdsa 0.17 `hazmat::verify_prehashed` rejects high-S only when `NORMALIZE_S`.
- **Parsing for verification** (`cms::parse`):
  - Use a **raw TLV walker** (~150 lines): definite **and BER indefinite** lengths, depth ≤ 32, every slice bounds-checked. It keeps raw slices for: the ContentInfo outer element; SignedData; each certificate; each SignerInfo; `sid`; **`signedAttrs` (the `[0]` element bytes exactly as found)**; `signature`.
  - Typed decoding with `der`/`x509-cert` happens only on leaves: attribute values, AlgorithmIdentifiers, certificates as `CertificateInner<Raw>`.
  - **Reasons, each verified in source:**
    1. der 0.8.2 `SetOfVec::decode_value` **sorts at decode time** in DER mode (`set_of.rs:626-636`). Decoding `SignerInfo` with `cms` types and re-encoding therefore changes the bytes of unsorted signed attributes. That breaks signatures pyHanko accepts, since asn1crypto verifies the original bytes. OpenSSL re-encodes and would fail; that is a known OpenSSL/pyHanko differential and we follow pyHanko.
    2. `cms::SignedData.certificates` uses the `Rfc5280` x509 profile, which rejects serials longer than 21 octets (`x509-cert 0.3.0 serial_number.rs MAX_DECODE_LEN`). One odd certificate would make the whole CMS unparseable.
    3. Some signers emit BER (indefinite-length) outer structures.
  - Non-DER signed attributes give a `warning` ("signedAttrs not DER; OpenSSL would reject"), never failure.

### 4.4 `PreparedSignature` invariants (checked by `from_bytes`, serde `try_from`, `finish` and `embed_cms`)
- version == 1
- `pdf[a] == b'<'`, `pdf[b-1] == b'>'`, all digits between are `'0'` (unfinished)
- the ByteRange text at its recorded offset re-parses to `[0 a b c]` with `b + c == pdf.len()`
- `H(pdf[0..a] ‖ pdf[b..])` equals `document_digest`, and `signed_attrs_der` contains that `message-digest`
- `chain_der[0]` parses and its key kind matches `key_kind`
- `finish(sig)`:
  - normalise and verify `sig` with `chain_der[0]` over `to_be_signed()`, else `SignatureInvalid`
  - `assemble`, then `len ≤ R` (else `PlaceholderTooSmall { needed, reserved: R }`), then patch hex
- `embed_cms(cms)`:
  - `cms::parse`, then exactly one SignerInfo, then detached; `message-digest == document_digest` (else `SignatureInvalid`, "CMS signs different bytes")
  - the signature verifies with the CMS's signer certificate
  - for `EtsiCadesDetached`, the B-B profile must hold: content-type, ESS v2 matching, no signing-time; else `InvalidArgument`. Folioxide never labels a non-B-B CMS `ETSI.CAdES.detached`.
  - size check as for `finish`

### 4.5 Field placement rules (pyHanko `DEFAULT_DIFF_POLICY` compatibility)
- **`FieldMode::CreateOrUse` with a name:**
  - If an existing terminal field with that FQN has `/FT /Sig` (inherited allowed) and no `/V`, sign it: set `/V` on the field object only. The widget is already on its page.
  - If the field is already signed, `InvalidArgument`. If the field is not a signature field, `InvalidArgument`.
  - Otherwise create a new root-level field.
  - `ExistingOnly` gives `NotFound` when the field is absent. `CreateOnly` gives `InvalidArgument` when the name exists.
- **No name:** create `Signature{n}`, with the smallest `n ≥ 1` not used by any FQN. Never take over an existing empty field implicitly (D-18).
- **Names containing `.`** give `InvalidArgument` (§12.7.4.2). The page index must exist (`PageOutOfRange`; a 0-page document can't be signed).
- **A field with `/Lock`** (FieldMDP) gives `Unsupported` (M11). **A field with `/SV`** whose `/Ff` marks any constraint as required gives `Unsupported` (D-13).
- **`/AcroForm`:**
  - absent: a new **indirect** dict `<</Fields [W 0 R] /SigFlags 3>>`, and the catalog gains `/AcroForm A 0 R`
  - direct in the catalog: edit the catalog
  - indirect: edit that object
  - **indirect `/Fields`:** edit the array object
- **`/SigFlags`:**
  - set to 3 **only if the document has no signed signature field yet**
  - if one exists, **no AcroForm key other than `/Fields` changes** (D-6). pyHanko's `FormUpdatingRule` compares every AcroForm key except `/Fields /DR /DA /Q /NeedAppearances`; a `/SigFlags` change would make *earlier* signatures `OTHER`.
  - `/NeedAppearances` is left untouched, with a warning when it is true (D-5).
- **Page `/Annots`:** absent means add `[W 0 R]` to the page dict. Direct means edit the page. Indirect means edit the array.

## 5. Verification algorithm (A.6.7 made concrete for M3)
**V0. Input.**
- A `Document` with no pending edits (`store.is_modified()` gives `InvalidArgument`, D-8).
- Resolve **every** in-use object once (`object_ids()` + `resolve`; linear by D9.7), so `recovered_objects()` is complete and orphans can be found. The streams of the signed ranges are hashed straight from `store.source()`.

**V1. Discovery.**
- Walk `/AcroForm /Fields` with `/Kids` recursion: depth ≤ 32, a cycle set by `ObjectId`, `/FT` inherited, FQN = `/T` parts joined with `.`.
- Every terminal field with `/FT /Sig` and a `/V` is a candidate.
- `/V` must be an **indirect** reference to a dictionary (else `SigValueNotIndirect` / `SigDictNotDictionary`).
- A sig dict referenced by two fields is reported for each field, with a warning.
- **Orphans:** every dict with `/Type /Sig` or `/DocTimeStamp` that also has `/ByteRange` or `/Contents` and that no field's `/V` references. They are reported with `field_name = None` and problem `Orphan`.
- **Order:** by `b+c` (signing order, as `validate_sig.py`), orphans last.
- `/Type /DocTimeStamp` or SubFilter `ETSI.RFC3161` gives `kind = DocTimeStamp`, `PendingTimestampVerification` (M4), and `signature_valid = false`.

**V2. Signature dictionary.**
- `/SubFilter`:
  - `ETSI.CAdES.detached` or `adbe.pkcs7.detached`: detached route
  - `adbe.pkcs7.sha1`: verify-only route. `eContent` = SHA-1 of the ranges; `message-digest` = H(eContent); `WeakAlgorithm`. Optional in M3 (Minor if missing).
  - anything else: `UnsupportedSubFilter`, `signature_valid = false`
- A missing or unexpected `/Filter` gives a warning only.

**V3. ByteRange** (USF and SWA defence):
- `/ByteRange` must be a **direct** array (`ByteRangeIndirect`; an indirect array could live in an unsigned later revision).
- It holds exactly 4 `Object::Int` (no reals), each ≥ 0, with `o1 == 0`, `l1 > 0` and `o1+l1 < o2`.
- `o2 + l2 ≤ file_len`, using `checked_add`.
- Problems: `ByteRangeMissing`, `ByteRangeMalformed`, `ByteRangeNotFromZero`, `ByteRangeOutOfBounds`.
- **`intact`** (V6) is computed over the pairs **as written** whenever every pair is non-negative and within the file, even if it is not 4 values. That agrees with pyHanko's `byte_range_digest`.

**V4. Contents and gap** (SWA defence):
- `/Contents` must be a direct hex string (`ContentsMissing` / `ContentsNotHex`; a literal string, `null` or `<>` all fail).
- `store.object_location(sig)` must be `InFile { start, end }` (else `SigDictCompressed`: an ObjStm-compressed dict can never exclude its `/Contents`).
- Re-lex `[start, end)`. The value token of key `/Contents` at dict depth 1 must span exactly `[a, b) = [o1+l1, o2)` (else `GapNotContents`).
- The sig dict object must lie inside the signed bytes: `end ≤ o2 + l2` (else `SigDictOutsideSignedRange`).
- The decoded token must equal the parsed `/Contents` bytes, as in `extract_cms`'s gap check.
- Non-zero bytes after the outer DER element give a warning only (pyHanko ignores them, D-19).
- `byte_range_ok` = no V3/V4/V5-structural problem.

**V5. Revision and coverage** (ISA and SWA defence; pyHanko's algorithm):
- `len != 4 || o1 != 0` gives `Unclear`.
- `byte_range_ok && o2+l2 == file_len` gives `EntireFile`.
- A gap that is not this dict's `/Contents` gives `Unclear`.
- Otherwise find `k` with `revisions[k].eof_end == o2+l2`, or `eof_end − (o2+l2) ≤ 2` with only CR/LF in between. Every `section_end` of revisions `0..=k` must be ≤ `o2+l2`.
- The sig dict's **last listing** (the newest revision whose `revision_entries` lists its number) must be ≤ `k`; else `SigDictRedefinedLater`.
- Pass: `EntireRevision`, `signed_revision = k`. Fail: `ContiguousBlockFromStart` (+ `SignedRevisionNotInChain`, which also catches an appended update whose `/Prev` skips the signed revision).
- For linearized files, `eof_end` is not monotonic; match against **any** revision (A.6.7).

**V6. intact.**
- `H_d(ranges) == message-digest`, with `d` = `SignerInfo.digestAlgorithm`.
- If signedAttrs are absent (legal for `adbe.pkcs7.detached`): `intact = signature_valid` (pyHanko).

**V7. CMS** (`cms::verify_detached`):
- ContentInfo type is signedData; exactly one SignerInfo (`SignerInfoCount`); `eContentType` = id-data and **no eContent** on detached routes (`EContentPresent`).
- signedAttrs: exactly one `content-type`, equal to `eContentType`; exactly one `message-digest`.
- `signing-certificate-v2` or v1, if present, must match the signer cert. Check certHash, plus `issuerSerial` when present (`SigningCertificateMismatch`).
- `CMSAlgorithmProtection` (1.2.840.113549.1.9.52), if present, must match (`AlgorithmProtectionMismatch`).
- The signer cert is found by `sid`, either IssuerAndSerialNumber (raw compare) or SKI (`SignerCertNotFound`).
- The signature is verified over the **original** signedAttrs bytes with byte 0 replaced by `0x31`.
- **RSA PKCS#1 v1.5:**
  - A signature shorter than `k` is left-padded with zeros, which agrees with OpenSSL/pyHanko. rsa rc.19 `pkcs1v15.rs:216` rejects a signature whose `bits_precision` differs from the modulus.
  - Longer than `k`: invalid.
  - Keys of 1024–8192 bits; < 2048 gives a warning.
- **RSA-PSS:** via `rsa::pss` with the salt length from the parameters.
- **ECDSA P-256/P-384:** via `PrehashVerifier::verify_prehash(H(tbs))`, which allows any digest/curve pairing; DER or P1363.
- **Hash consistency:** a hash implied by `signatureAlgorithm` that differs from `digestAlgorithm` gives `DigestSignatureAlgorithmMismatch` and `signature_valid = false`.
- **Weak algorithms:** SHA-1 gives `WeakAlgorithm`; the crypto check is still reported and `trusted = false` (agrees with pyHanko).

**V8. PAdES profile:**
- `pades_level = Some(BB)` iff every condition holds: SubFilter `ETSI.CAdES.detached`, content-type, message-digest, ESS v2 matching and no v1, no signing-time, signer cert in certificates, single signer, detached, `/M` present, no `/Cert`.
- Unsigned signature-timestamp attributes are only listed in M3.

**V9. Certificates and trust** (A.6.7 step 7):
- `signer` and `chain` (every CMS cert, in file order) as `CertificateInfo`.
- With anchors:
  - Build a path from the signer through the CMS certs plus `extra_certs` to an anchor; ≤ 8 links, ≤ 64 candidates.
  - Verify each certificate signature: RSA PKCS#1, PSS, ECDSA P-256/P-384.
  - Validity at `validation_time` (None means `/M` plus a warning "validated at the signer's claimed time").
  - Issuers need `basicConstraints cA` (with pathLen respected) and, when KU is present, `keyCertSign`.
  - The signer KU, when present, needs digitalSignature **or** nonRepudiation (D-10).
  - Any unknown **critical** extension makes the result untrusted. No revocation, no network.
- `trusted = Some(bool)` with anchors, else `None`.

**V10. Modification (basic)**, for `j > k` (ISA and shadow defence):
- **Changed set** `C` = ⋃ `revision_entries(j)`. For a hybrid section this is the **union** of the table and its `/XRefStm`, every free and null entry included, so a change cannot hide in the half another reader prefers.
- An entry identical to the entry in force at revision `k` (same location and generation) is a **re-listing** and gives `LtaUpdates` (probe `C_relist`: pyHanko `LTA_UPDATES`).
- Then classify each `id ∈ C`:
  1. A **new** number (≥ the revision-`k` `/Size`, never listed or used before) that is:
     - a new sig field or widget dict (`/FT /Sig`, invisible): `LtaUpdates`
     - the sig dict that a new or existing field's new `/V` points to: `FormFilling`
     - a new xref-stream object of section `j`: allowed
     - an object reachable only from those: its own level
     - **any other new object reachable from the catalog**: `Other`
  2. **Catalog:** every key except `/AcroForm /DSS /Extensions /Metadata /MarkInfo /Version` must be unchanged, compared raw. `/AcroForm` changes are allowed only as in (3). `/DSS` gives `Other` in M3 (D-9 list). A `/Metadata` stream replacement gives `LtaUpdates`. Anything else gives `Other`.
  3. **AcroForm:** every key except `/Fields /DR /DA /Q /NeedAppearances` must be unchanged. In `/Fields`, every old field must still be present, and every added entry must be a new root-level sig field.
  4. **An existing field:** only an unsigned `/FT /Sig` field gaining `/V`, `/AP` or `/AS`, `/F` or `/Ff` gives `FormFilling`. Any change to a signed field, or to any non-signature field, gives `Other` in M3.
  5. **A page dict or `/Annots` array:** only appending references to new sig widgets gives `LtaUpdates`. Every other key must be unchanged (raw).
  6. **The trailer `/Info` dict object, or `/Info` pointing to a new dict:** `LtaUpdates`.
  7. **Freeing anything, a changed generation, or changing an existing object stream container** (its members would change without being listed): `Other`.
  8. **Everything else:** `Other`.
- **Trailer checks:** a newest `/Root` that differs from revision `k`'s `/Root` without being listed in any section `j > k` gives `Other` (the Hide-and-Replace root switch). An `/Encrypt` change gives `Other`.
- **Repairs:**
  - If `coverage == EntireFile`: `None`, with a warning naming the repair (all bytes are signed).
  - Otherwise, if `structure_repaired()` or `recovered_objects()` is non-empty: `Other` + `StructureRepaired`, with the diagnostic kinds in the message. This covers `UnreferencedUpdate`, a bad `startxref`, scan-only objects, short `/Length` and generation repairs.
- `modification` = the maximum; `changed_objects` = the sorted `C`.
- **No appended revisions and no repair:** `None`. With trailing non-update junk, coverage is `EntireRevision` and modification `None` (agrees with probe `E_comment`).

**V11.** `docmdp` comes from `/Reference … /TransformParams /P` or `/Perms /DocMDP`. `docmdp_ok = None` until M4.

**V12.** Assemble the report; `is_valid()` as defined in §3.2.

- **one per xref shape:** `xref-stream`, `hybrid`, `objstm`, `xref-stream-incremental`, `multi-revision`, linearized
- **other options:** `adbe.pkcs7.detached`, and the explicit-small-reserve retry
- **untrusted signers:** `wrong-ku` and `expired`, both with `trusted: false`

**`sign-tamper`**: at least 3 cases, each with `intact: false`, so pdfsig and openssl must fail.
- A byte flip in page content (part 1).
- A byte flip in the widget `/T` (part 2).
- Non-zero bytes after the CMS inside `/Contents`: intact and valid stay true, and `knownFailures: {"signatures[0].padding": "tamper: non-zero padding"}` is set.
- ROADMAP §M3 acceptance #3 is met when pyHanko and our `verify` both say `intact=false`. Assert ours in the emitting test.

**`sign-attacks`**: at least 12 checked cases, covering ISA, SWA and shadow.
- Expectations are pyHanko's column from §5.1.
- The SWA `gap` row goes through `knownFailures`.
- USF cases use the new `rejected: true` entry key (D-3). Until that key exists they use `oracleSkip` with the reason "pyHanko raises PdfReadError (agrees: not valid)", and QA re-runs the probe by hand.

### 6.4 Node (`cd bindings/node && pnpm build && pnpm test && pnpm test:types`)
`test/sign.test.mjs` covers:
1. **`.p12` signing:** `signPdf` with `LocalSigner.fromPkcs12(signer-rsa2048-modern.p12, 'folioxide')`, then `verifySignatures({trustAnchors:[root]})` returns one report with `intact`, `signatureValid`, `byteRangeOk` and `trusted` all true, `coverage === 'entireFile'`, `modification === 'none'` and `signer.subject === 'CN=Folioxide Test Signer RSA-2048,OU=TEST ONLY - DO NOT TRUST,O=Folioxide Test PKI'`.
2. **PEM signing:** with `signer-p256.key.pem` + the `[signer, intermediate]` PEM, and with `signer-p384.key.enc.pem` + password.
3. **Key-loading errors:** a wrong p12 password gives `E_WRONG_PASSWORD`; an encrypted PEM with no password gives `E_PASSWORD_REQUIRED`; garbage gives `E_KEY_LOAD`; no message contains the password.
4. **External RSA signer:** `node:crypto.sign('sha256', tbs, rsaKey)`.
5. **External ECDSA P-256 signer:** `crypto.sign('sha256', tbs, {key, dsaEncoding: 'ieee-p1363'})`, and again with `'der'`.
6. **External P-384 signer:** with `digest: 'sha384'`.
7. **Async external signer:** a `Promise` with `setTimeout` resolves correctly, and two `signPdf` calls run concurrently on two documents.
8. **Wrong key:** an external signer that signs with another key throws `E_SIGNATURE_INVALID`.
9. **Serialization:** `prepareSignature` → `serialize` → `deserialize` → `finish` is byte-identical to finishing directly; a second `finish` gives `E_INVALID_ARGUMENT`.
10. **Too-small reserve:** `prepareSignature({contentsReserve: 100, …})` throws `E_SIGNATURE_PLACEHOLDER_TOO_SMALL` with `err.details.needed > 100`.
11. **Sequential signatures:** after two signatures, `reports[0].coverage === 'entireRevision'` and `reports[0].modification === 'formFilling'`.
12. **Tamper:** flipping a byte inside the signed range gives `intact === false`.
13. **Prefix:** `out.subarray(0, input.length).equals(input)`.
14. **Busy rule:** a sync `prepareSignature` during `verifySignatures` either throws `E_BUSY` or completes, without deadlock.
15. **Report fields:** the unicode `reason` round-trips in the report.

Type tests cover `signPdf`, `LocalSigner`, `PreparedSignature`, `SignatureReport` and `ExternalSigner`.

## 7. Risk register (top pitfalls)
| # | Risk | Mitigation / test |
|---|---|---|
| R-1 | The ByteRange width changes, shifting every later offset | Fixed 10-digit placeholder, space padding, assert equal length: `placeholder_byterange_width_constant`, `byterange_patch_no_leading_zeros` |
| R-2 | Last revision is an xref stream vs a table vs a hybrid | M2 writes the same kind (a stream after a hybrid); the sig dict is never compressed. `sign_every_syntax_fixture` plus `sign-bb` cases per kind (pyHanko non-strict accepts hybrids; I probed pyHanko signing on hybrid, xref-stream, objstm and xref-stream-incremental: all `ENTIRE_FILE`) |
| R-3 | A repaired structure (`structure_repaired()`): the signed revision may not be what qpdf, poppler or pdf.js show | Refuse signing (M2 refusal; message names existing signatures). Verify: `Other` + `StructureRepaired` unless `EntireFile`. `sign_refuses_repaired_structure` |
| R-4 | Sig dict, `/Contents` or `/ByteRange` in an object stream, or `/Contents` written as a literal string or with whitespace | Overlay never compresses; hex with no whitespace; verifier `SigDictCompressed` / `ContentsNotHex` |
| R-5 | Junk before `%PDF-`: ByteRange is file-absolute while xref offsets are header-relative | **pyHanko cannot read such files** (probe: `PdfReadError: Illegal PDF header`), so an oracle-backed result is impossible. Refuse signing (D-2): `sign_refuses_junk_before_header`. Verification works with absolute offsets |
| R-6 | Documents with existing signatures: `/SigFlags`, `/NeedAppearances` or AcroForm-key changes make earlier signatures `OTHER` in pyHanko | §4.5 rules; `second_signature_keeps_acroform_keys`; oracle two/three-signature cases plus the case after pyHanko |
| R-7 | Reusing a freed object number for new objects reads as clobbering in pyHanko | `next_object_number()` above every listed number: `next_object_number_skips_freed` |
| R-8 | Existing unsigned fields: `/Lock`, `/SV`, inherited `/FT`, `/Kids` widgets | §4.5; `field_existing_empty_used`, `field_lock_unsupported` |
| R-9 | RSA timing (RUSTSEC-2023-0071, unpatched; the advisory says default-path blinding is still pending in RSA#702) | Use `RandomizedSigner::try_sign_with_rng` (verified: the plain `Signer` path is unblinded in rc.19). Docs recommend ECDSA or KMS for servers (D5.4). Re-check on each `rsa` release |
| R-10 | ECDSA encodings: P1363 vs DER ambiguity, non-minimal INTEGERs from KMSes, high-S | §4.3 normalisation plus verify-before-embed; `ecdsa_*` tests; high-S accepted (P-256 `NORMALIZE_S=false`) |
| R-11 | RSA-PSS verification: parameter decoding, MGF1 hash, salt length | §4.3; `verify_rsa_pss_openssl_fixture` (committed openssl `-keyopt rsa_padding_mode:pss` CMS) |
| R-12 | SHA-1 or legacy signatures | Verify only; `WeakAlgorithm`; trusted false (agrees with pyHanko's `DEFAULT_WEAK_HASH_ALGORITHMS`); never signs with SHA-1 |
| R-13 | Re-encoding foreign CMS changes the signed attributes (der `SetOfVec` sorts on decode) | Raw-slice TLV parser: `cms_parse_keeps_unsorted_signed_attrs` |
| R-14 | Signing a certified P=1 document produces an invalid document | Read `/Perms /DocMDP` and refuse with `DocMdpForbids`: `sign_refuses_certified_p1` (fixture made by pyHanko `certify`) |
| R-15 | Placeholder overflow | Exact `needed` computed before signing (§4.2), so overflow is impossible on `finish` in M3. `embed_cms` reports `{needed, reserved}`; `sign()` retries once only for an explicit reserve |
| R-16 | `PreparedSignature` tampered or persisted across versions | Versioned binary format, invariants re-checked (§4.4): `prepared_signature_tamper_rejected` |
| R-17 | Linearized inputs: `eof_end` is not monotonic, and the newest logical section is at the start | Match `b+c` against any revision; add a linearized fixture (`tools/fixtures`, pikepdf `linearize=True`) to `sign-bb` |
| R-18 | Hostile CMS or PDF input: deep nesting, huge cert sets, bignum DoS | Depth 32, ≤ 64 certs and attrs, RSA ≤ 8192 bits (`RsaPublicKey::MAX_SIZE`), checked arithmetic; fuzz `fuzz_cms_parse`, `fuzz_verify`; `no_panic_verify_mutated_signed` |
| R-19 | Trust-time ambiguity (there is no clock in the core) | `VerifyOptions.validation_time`; Node passes `Date.now()` (agrees with pyHanko); Rust `None` means `/M` plus a warning |
| R-20 | Large files: memory and 10-digit limit | Streamed hashing; `PreparedSignature` holds one copy; `InvalidArgument` beyond 9,999,999,999 bytes |
| R-21 | pyHanko quirks in oracles: its signer fails on `multi-revision.pdf` (a freed `/Info`: `TypeError` in `pdf_date`); `trusted` was flaky in an ad-hoc probe that reused one `ValidationContext` (the runner's fresh context per signature is fine) | Only pyHanko *validation* is an oracle; pyHanko-signed fixtures are generated from `minimal.pdf`-style inputs |

## 8. Open decisions: all accepted by the manager on 2026-10-10 as recommended (DECISIONS D10)
1. **D-1 RNG for RSA blinding.**
   - Recommend a default-on feature `sys-rng` on `folioxide-sign` using `getrandom 0.4.3` `SysRng` (`rand_core::UnwrapErr` adapter, `rand_core 0.10`), with an override `LocalSigner::with_rng`.
   - wasm later needs `getrandom/wasm_js`.
   - This is the "OsRng-style helper" already allowed by A.4.
2. **D-2 Junk before the header.** Recommend refusing signing with `Unsupported` ("save a full copy first"); evidence in R-5.
3. **D-3 Oracle runner key `rejected: true`** inside a `signatures[]` entry.
   - It passes when pyHanko raises or reports intact/valid False for that field, pdfsig does not print "Signature is Valid.", and openssl or extraction fails; structure rows are skipped.
   - This changes D7.6 and A.9. Recommend yes (about 40 lines, Dev B stage 2), so that USF stays mechanically oracle-checked.
4. **D-4 Enum vocabulary.** Recommend `Coverage` and `ModificationLevel` exactly as pyHanko's (§3.2), replacing A.6.7's `Signing`/`LtaOnly`/`Revision(k)`, and updating ARCHITECTURE A.6.7.
5. **D-5 `/NeedAppearances`.** Recommend leaving it untouched, with a warning. pyHanko deletes it when signing; deleting it can blank fields that have no `/AP` until M8 can generate appearances.
6. **D-6 `/SigFlags`.** Recommend setting 3 only when no signed field exists; otherwise touch no AcroForm key except `/Fields`.
7. **D-7 Exact CMS sizing** (§4.2) replaces A.6.2's 1.15 heuristic for M3, with a default of at least 8192 bytes. Update A.6.2.
8. **D-8 `verify` with pending edits:** recommend `InvalidArgument`.
9. **D-9 Stricter-than-pyHanko cases** (`UnreferencedUpdate` and repairs give `Other`; generic form fill, `/DSS` and annotations give `Other` in M3): recommend accepting them, consistent with D9.8, and recording the list in DECISIONS.
10. **D-10 Signer KU:** recommend digitalSignature **or** nonRepudiation (pyHanko: nonRepudiation only), documented as a deliberate difference.
11. **D-11 Validation time:** as R-19.
12. **D-12 RSA sizes:** sign with ≥ 2048 bits; verify ≥ 1024 bits (warning below 2048), up to 8192 bits.
13. **D-13 `/Lock` and required `/SV` constraints:** `Unsupported` in M3.
14. **D-14 Certified documents:** refuse P=1 even in M3. It is cheap and avoids producing documents that are invalid per §12.8.2.2.
15. **D-15 Orphans:** keep them in the same list with `fieldName: null`. The alternative is a separate field.
16. **D-16 Trust path building in M3** (Dev B stage 2): recommend yes. It is small, and a verifier without trust is of little use to the user.
17. **D-17 `PreparedSignature`:** an own versioned binary format (`to_bytes`), plus serde behind the feature. Node has no serde.
18. **D-18 Auto field naming:** never takes over an existing empty signature field. Named fields do.
19. **D-19 Non-zero bytes after the CMS in `/Contents`:** a warning only (agrees with pyHanko); the oracle row uses `knownFailures`.
