### 0.2 Folioxide's encryption rules (binding)

1. **Exemptions are one predicate, shared by the reader and both writers (§1.4).**
   - The encryption dictionary object.
   - Cross-reference streams.
   - Every trailer value.
   - Strings inside object streams.
   - Signature `/Contents`.
   - The catalog's `/Metadata` when `EncryptMetadata` is false (V4/V5).
   - `/Identity` crypt filters.
2. **Ciphertext strings are written in hexadecimal form.**
   - Reason: ciphertext as a literal string can hold `obj`, `trailer` or line breaks, which the M4 rebuild-proof scan (D14.2) would rightly treat as structure.
   - Decrypted strings keep the form flag of their ciphertext token.
3. **The source bytes stay ciphertext (trap #5, A.3).**
   - Strings are decrypted when their object is parsed.
   - Stream data is decrypted when it is decoded.
   - `raw_stream_data` still returns the file's bytes.
   - The new `encoded_stream_data` returns the decrypted bytes with their filters still applied.

## 1. Security design for hostile encrypted input

### 1.1 Threat model (documented in rustdoc and the Node README)
- **Confidentiality only against passive attackers.**
  - PDF encryption is unauthenticated (absent ISO/TS 32004).
  - Anyone who can modify a document can make any reader reveal its plaintext (Müller et al., "Practical Decryption exFiltration", CCS 2019).
  - Folioxide adds **no oracle** beyond showing decrypted content: no observable value (error code, diagnostic, classifier level, timing beyond plaintext length) depends on padding validity or on whether decrypted bytes parse (§1.5, §5.4).
- **The owner password protects nothing.** Permissions are advisory (D5.2), and the owner password is not a security boundary.
- **RC4 is broken**, and the format reuses one RC4 key for every string and stream of an object. It is read for compatibility; writing it needs `allow_weak_crypto` (E13).

### 1.2 `/Encrypt` validation (a whitelist, read once at open)

The rules are checked in this order, and the first failure decides.
- **Shape:**
  - `/Encrypt` resolves to a dictionary that is an in-file object, or is direct in the trailer.
  - It is not a stream, not in an object stream (§7.5.7), and not the catalog or `/Info`.
  - Every value below is a **direct** object.
  - Every string is at most 256 bytes.
  - A violation is `E_UNSUPPORTED`, or `E_SYNTAX` for wrong types.
- `/Filter /Standard` is required. Another handler is `E_UNSUPPORTED`, and so is any `/SubFilter` (pypdf parity).

| V | R | `/Length` (bits) | CFM of StmF/StrF/EFF | File key | O, U | OE, UE, Perms |
|---|---|---|---|---|---|---|
| 1 | 2 | absent or 40 (any other value: diagnostic, ignored; Algorithm 2 step i fixes n = 5) | RC4 | 5 B | 32 B | — |
| 2 | 3 | absent (= 40) or 40..128, step 8 | RC4 | Length/8 | 32 B | — |
| 4 | 4 | absent or 128; CF `/Length` absent, 16 or 128 | `/V2`, `/AESV2`, `/None`, `/Identity` | 16 B | 32 B | — |
| 5 | 5 (read only) | absent or 256; CF `/Length` absent, 32 or 256 | `/AESV3`, `/None`, `/Identity` | 32 B | 48 B | 32, 32, 16 B |
| 5 | 6 | as R5 | as R5 | 32 B | 48 B | 32, 32, 16 B |

Notes on the table:
- **Rows not listed** (V3, R7+, (V2,R2), (V4,R6), …) are `E_UNSUPPORTED`.
- **O and U longer than listed:** lenient mode uses the prefix with a diagnostic; strict mode is `E_SYNTAX`. Shorter is always `E_SYNTAX`.
- **`/P`:** an integer in the 32-bit range, read as signed (trap #8; `(P + 2^32) mod 2^32`).
- **`/CF`:** a direct dictionary with at most 64 entries.
  - Every name used (StmF, StrF, EFF, and per-stream `/Name`) is `/Identity` or a `/CF` key.
  - A `/CF` key named `Identity` is ignored, with a diagnostic (strict: `E_UNSUPPORTED`).
  - `/AuthEvent /EFOpen` is accepted and treated as `/DocOpen`, since decryption is lazy anyway.
- **`/EncryptMetadata`:** a boolean, default true (Table 21). It is meaningful for V4/V5 only.
- **ISO/TS 32004:** `/KDFSalt` in `/Encrypt`, or `/AuthCode` in the trailer, sets `iso_mac = true` (diagnostic `Encryption`: "MAC not verified").

### 1.3 Location and consistency rules
- **Unlock order.** `/Encrypt` is resolved through `resolve_source` and is never decrypted. The store unlocks before any other slot is loaded.
  - Test `no_object_cached_before_unlock` checks that no slot, peek memo or object-stream cache entry exists at unlock.
  - `install()` already clears the caches.
- **Older trailers.** Every trailer in `revisions()` that has `/Encrypt` must name the same object, or a byte-identical direct dictionary, with the same `/ID[0]`.
  - Otherwise lenient mode gives diagnostic `Encryption` ("objects of earlier revisions may not decrypt", qpdf: newest wins); strict mode gives `E_XREF`.
  - The verifier makes every signature over such a file `Other` (§5.4).
- **`/ID`.** `/ID[0]` is taken from the effective trailer, as bytes of any length.

### 1.4 The exemption predicate (`folioxide_syntax::crypt`, one function used by the reader and both writers)

For object `id` with value `obj`, in this order:
1. **The `/Encrypt` object** (`binding.encrypt_id`): no strings, no stream data.
2. **Streams whose dictionary has `/Type /XRef`:** nothing decrypted, dictionary included (§7.5.8, qpdf parity).
3. **Every other in-file object:** every string at any depth (iterative walk) is decrypted with StrF. There is one exception: a **direct** `/Contents` string in a dictionary that `writer::is_signature_dictionary` accepts (D11.16: `/Type /Sig` or `/DocTimeStamp`, or `/ByteRange`, or `/Contents` with `/Filter` or `/SubFilter`) is kept raw (§12.8.1; E7).
4. **Stream data**, chosen by the first rule that applies:
   - `/Filter` whose first element is `/Crypt`: the `/DecodeParms` `/Name`, default `/Identity` (§7.4.10, Table 14; `/Type` optional); `/Crypt` elsewhere in the chain gives E5;
   - else the object is the **source** catalog's `/Metadata` and `EncryptMetadata` is false (V4/V5): plain;
   - else `/Type /EmbeddedFile`: EFF (default StmF);
   - else StmF.
5. **Objects inside object streams, and every trailer value:** never decrypted.

On the write side the same predicate runs on the object **being written** with its **target** id. For the metadata rule, the target's catalog `/Metadata` id is used.

### 1.5 Ciphertext handling and the no-oracle rule
- **AES strings and streams:** `IV(16) ‖ AES-CBC(PKCS#7)` (Algorithms 1 and 1.A). Lengths are key-independent facts and may be reported:
  - fewer than 32 bytes, or not a multiple of 16: diagnostic `Ciphertext` (strict: `E_CRYPTO`);
  - the output is still qpdf's: ≤ 16 bytes gives empty output, and a ragged tail is zero-filled and decrypted.
- **Padding is key-dependent, so it is never observable.**
  - The last block is unpadded **branch-free**: a validity mask over the 16 bytes (`subtle::ConstantTimeEq` / `ConditionallySelectable`), then a strip length of `pad` or 0.
  - When the padding is invalid, nothing is stripped (qpdf), with **no error in either mode and no diagnostic**.
  - Test `padding_never_observable`: two files that differ only in a padding byte give identical `Result` codes, identical diagnostics and identical verifier levels.
- **Password checks** compare with `ConstantTimeEq`: U/O hashes, the first 16 bytes of U for R3+, and Perms.
- **RC4** is table-indexed and not constant-time. That is accepted for a legacy cipher and documented.

### 1.6 Linear by construction
- **Algorithm 2.B ends by construction.**
  - Rounds are counted from 1, and the loop stops at `count ≥ 64 ∧ E[last] ≤ count − 32`. Since `E[last] ≤ 255`, it stops by round 287 at the latest.
  - The input per round is at most `64 × (127 + 64 + 48)` = 15,296 bytes.
  - Test `alg2b_round_bound` (proptest, 10k random inputs) asserts ≤ 287 rounds.
- **Password candidates:** at most 2. Each is tried as owner then user, so an open runs at most 4 checks plus one key unwrap. Test `open_r6_worst_case_within_budget` uses `budget::within`.
- **Decryption cost** is linear in the bytes decrypted.
  - Stream decryption counts against the existing per-source-stream decode budget, since output ≤ input.
  - String decryption runs inside the object parse and is bounded by `ObjStmParsed`/region bounds.
  - Test `hostile_encrypted_default_limits` covers 10^5 strings in one object, 10^4 encrypted streams, a 1 MB `/ID`, 64 crypt filters, and encrypted object streams with `/Extends` chains.

### 1.7 Key material hygiene
- **Zeroized and never printed.** These are held in `Zeroizing` and never appear in `Display`, `Debug`, errors or diagnostics:
  - file keys, per-object keys and intermediate hashes (`K`, `E` in 2.B);
  - passwords and candidates;
  - the seed (§1.8).
- **Redacted `Debug`.** `Password`, `StandardCrypt`, `EncryptionSettings` and `OpenOptions.password` print `<redacted>`.
  - `Store`'s `Debug` prints `encrypted: true`.
  - `OpenOptions`' `serde` skips serializing `password` (deserialize from a string only).
- **No `Serialize` on secrets.** `EncryptionSettings` has no `Serialize`.
- Test `no_key_material_in_errors` uses password `S3cret-Password-Ω` on every fixture and every error path (wrong password, unsupported dictionary, malformed ciphertext, strict errors, saves, signing). It asserts that no error string, diagnostic message or `{:?}` contains:
  - the password, in UTF-8 or as hex;
  - the file key, in hex or Base64;
  - the O/U/OE/UE hex.

### 1.8 Randomness and determinism (no ambient RNG)
- **New R6 encryption** needs 32 secret bytes. The caller passes `seed: [u8; 32]` from a CSPRNG in `EncryptionSettings`. The facade adds `EncryptionSettings::with_random_seed` behind `sys-rng`, and the Node binding draws from the OS. Everything is derived from the seed with HMAC-SHA-256 and a label:
  - `file_key = HMAC(seed, "folioxide/v1/file-key")`;
  - the four 8-byte salts = `HMAC(seed, "folioxide/v1/salts")[0..32]`;
  - the Perms filler = `HMAC(seed, "folioxide/v1/perms")[0..4]`;
  - ID[0] for a document without `/ID` = `HMAC(seed, "folioxide/v1/id")[0..16]`.
- **R2–R4** need no randomness except ID[0].
- **AES IVs, synthetic and deterministic, for every string and stream Folioxide encrypts**, new encryption and incremental updates alike:
  - `k_iv = HMAC(file_key, "folioxide/v1/iv")`;
  - `IV = HMAC(k_iv, num_be32 ‖ gen_be16 ‖ kind_u8 (0 string, 1 stream) ‖ ordinal_be32 ‖ SHA-256(plaintext))[0..16]`, where `ordinal` is the string's index in the object's serialization order.
  - The IV is unpredictable without the key and unique per (object, position, content), so it leaks only that an unchanged string re-saved at the same place is unchanged.
  - Output is byte-deterministic for a given seed (golden tests; `deterministic_encrypted_save`).
- Never reuse a seed. This is documented, and the Node binding never takes one from JavaScript.

**`ImportSession` validity.** Each call checks:
- the session's source and target are the documents passed (`Weak::ptr_eq` on upgrade; a live `Weak` keeps the allocation, so addresses are never reused);
- the source `epoch` is unchanged since the session started;
- a mapped target id still `contains()`; otherwise it is copied again.

A failure is `E_INVALID_ARGUMENT`. There is no global counter (CLAUDE.md: no global mutable state). Importing from the target itself is `E_INVALID_ARGUMENT`.

**Error codes.**
- `E_PAGE_OUT_OF_RANGE` for an index or range end past the last page.
- `E_INVALID_ARGUMENT` for:
  - a non-permutation;
  - duplicate indices in `move`/`reorder`;
  - an empty or reversed range;
  - a rotation that is not a multiple of 90;
  - a box outside the media box (bleed, trim, art are clipped to it as the crop box is, D11.12).
- `E_SIGNED_DOCUMENT` / `E_DOC_MDP_FORBIDS` per §5.1.
- `E_PERMISSION_DENIED` per D-9.
- No `E_PAGE_RANGE` code is added.

**Binding rules.**
- **Passwords** follow the `LocalSigner` rules: strings are copied into `Zeroizing`; byte arrays are read in place and used verbatim, with no SASLprep.
- **Seeds** for `save({encryption})` come from `getrandom`; JavaScript never sees them.
- **Cross-document calls:**
  - sync calls `try_lock` the target and every source and throw `E_BUSY` if any is busy;
  - async calls take `Pending` guards on every document at the call, and lock in ascending `Arc` pointer order on the pool, so they cannot deadlock;
  - `source === target` is `E_INVALID_ARGUMENT`.
- **New documents** from `extract`, `split` and `merge` report their own native memory.

## 4. Byte-level and algorithm-level specification

Clause numbers follow ISO 32000-2:2020 as the expert recalls them (§10 says what to check).

### 4.1 Algorithms
| Algorithm | Clause | Definition (n = file key length in bytes) |
|---|---|---|
| 1 (RC4, AESV2 per object) | §7.6.3 | `k = MD5(fk[0..n] ‖ num_le[0..3] ‖ gen_le[0..2] [‖ "sAlT" for AESV2])[0..min(n+5,16)]`; RC4 over the data, or `IV ‖ AES-128-CBC-PKCS7` |
| 1.A (AESV3) | §7.6.3 | `fk` (32 B) directly; `IV ‖ AES-256-CBC-PKCS7` |
| 2 (fk, R2–R4) | §7.6.4.3.2 | `MD5(pad32(pw) ‖ O ‖ P_le32 ‖ ID0 [‖ FF FF FF FF if R ≥ 4 ∧ ¬EncryptMetadata])`; R ≥ 3: 50 × `MD5(h[0..n])`; `fk = h[0..n]`, n = 5 for R2 |
| 2.A (fk, R6) | §7.6.4.3.3 | password processing per §4.3; owner first: `2.B(pw, O[32..40], U[0..48]) == O[0..32]` ⇒ `fk = AES-256-CBC-dec(IV 0, no pad, key 2.B(pw, O[40..48], U[0..48]), OE)`; else user: `2.B(pw, U[32..40], "") == U[0..32]` ⇒ `fk = AES-256-CBC-dec(…, 2.B(pw, U[40..48], ""), UE)`; then Algorithm 13 |
| 2.B (hash, R6) | §7.6.4.3.4 | `K = SHA-256(pw ‖ salt ‖ u)`; for count = 1, 2, …: `K1 = (pw ‖ K ‖ u) × 64`; `E = AES-128-CBC(key K[0..16], IV K[16..32], K1, no pad)`; `(Σ E[0..16]) mod 3` selects SHA-256, -384 or -512; `K = H(E)`; stop when `count ≥ 64 ∧ E[last] ≤ count − 32`; return `K[0..32]` (pypdf `calculate_hash`) |
| R5 (read only) | Adobe Supplement to ISO 32000, ExtensionLevel 3, Algorithm 3.2a | 2.A with `2.B` replaced by `SHA-256(pw ‖ salt ‖ u)` |
| 3 (O, R2–R4) | §7.6.4.4.2 | `rk = MD5(pad32(owner or user))`, R ≥ 3: 50 × MD5; `rk[0..n]`; `O = RC4(rk, pad32(user))`; R ≥ 3: 19 further passes with `rk ⊕ i`, i = 1..19 |
| 4 (U, R2) | §7.6.4.4.3 | `U = RC4(fk, PAD)` |
| 5 (U, R3/R4) | §7.6.4.4.4 | `x = RC4(fk, MD5(PAD ‖ ID0))`, then 19 passes with `fk ⊕ i`; `U = x ‖ 16 × 0x00` (the spec says arbitrary padding) |
| 6 (user, R2–R4) | §7.6.4.4.5 | recompute U from the candidate; compare all 32 bytes (R2) or the first 16 (R3+), constant time |
| 7 (owner, R2–R4) | §7.6.4.4.6 | `rk` as in 3; decrypt O (R2: once; R3+: 20 passes, `rk ⊕ i` for i = 19..0) to get a user candidate; then Algorithm 6 |
| 8 (U, UE) | §7.6.4.4.7 | `U = 2.B(pw, vs, "") ‖ vs ‖ ks`; `UE = AES-256-CBC(IV 0, no pad, 2.B(pw, ks, ""), fk)` |
| 9 (O, OE) | §7.6.4.4.8 | as 8 with `u = U` (48 B) |
| 10 (Perms) | §7.6.4.4.9 | `AES-256-ECB(fk, P_le32 ‖ FF FF FF FF ‖ ('T' or 'F') ‖ "adb" ‖ filler4)` |
| 11, 12 (authenticate user, owner; R6) | §7.6.4.4.10–11 | the tests of 2.A |
| 13 (validate Perms) | §7.6.4.4.12 | decrypt Perms; bytes 9–11 `adb`, bytes 0–3 LE = P, byte 8 = EncryptMetadata; otherwise §0.1 "/Perms mismatch" |

`PAD` is the 32-byte padding string `28 BF 4E 5E 4E 75 8A 41 64 00 4E 56 FF FA 01 08 2E 2E 00 B6 D0 68 3E 80 2F 0C A9 FE 64 53 69 7A`.

### 4.2 Strings and streams
- **Strings:** the key of the indirect object that holds them (direct strings inside it use its id).
  - AES output is `IV(16) ‖ CBC`, so an empty plaintext gives 32 bytes.
  - Ciphertext is written as `<hex>`.
- **Streams:** encryption applies to the filter-encoded bytes (§7.3.8).
  - `/Length` is the ciphertext length; `/DL` is unchanged.
  - A per-stream `/Crypt` filter stays first in `/Filter`.
- **Full save with `Keep`:**
  - R2–R4: every object is decrypted with its source id and encrypted with its target id.
  - R5/R6: source ciphertext is copied verbatim when the exemption result and `CryptUse` are equal on both sides (a pure optimization; test `keep_r6_fast_path_bytes_equal`).

### 4.3 Password processing (`password::candidates`)
| Input | R2–R4 | R5/R6 |
|---|---|---|
| `None` | `[""]` | `[""]` |
| `Text(s)` | `[PDFDoc(s)]` when encodable (`syntax::text::pdfdoc`), then `UTF-8(s)` if different; each truncated to 32 bytes (Algorithm 2 step a) | `[UTF-8(SASLprep(s))]` when SASLprep succeeds, then `UTF-8(s)` if different; each truncated to 127 bytes |
| `Bytes(b)` | `[b]` | `[b[0..min(127)]]` |

- **Order:** each candidate is tried as owner, then as user, before the next candidate.
- **Errors:** no candidate matching is `E_WRONG_PASSWORD`, or `E_PASSWORD_REQUIRED` when the input was `None`.
- **Writing** uses the first candidate only, under the E11/E12 rules.

### 4.4 Permission bits (Table 22)
- **Bit values:**

  | Bit | Value | Permission |
  |---|---|---|
  | 3 | 4 | print |
  | 4 | 8 | modify |
  | 5 | 16 | copy |
  | 6 | 32 | annotate |
  | 9 | 256 | fillForms |
  | 10 | 512 | accessibility |
  | 11 | 1024 | assemble |
  | 12 | 2048 | printHighQuality |

- **Write:** `P = (0xFFFF_F0C0 | granted) as i32`.
  - Bits 1–2 are 0; bits 7–8 and 13–32 are 1. Bit 13 set keeps pyHanko from requiring a MAC.
  - For R2, bits 9–12 are written as 1.
  - For R6, bit 10 is always 1 (deprecated in PDF 2.0).
  - Examples: all permissions give `-4`; none give `-3904`.
- **Read:**
  - R2: bits 9–12 are reported as granted when bits 4/6 grant them (pikepdf's reading; probe P-1).
  - `access = Owner` means every permission is effective.

### 4.5 The `/Encrypt` dictionary written (an indirect object, never compressed, never encrypted, hex strings)
- **RC4-40:** `<< /Filter /Standard /V 1 /R 2 /Length 40 /O <32> /U <32> /P p >>`. Header ≥ 1.1.
- **RC4-128:** `<< /Filter /Standard /V 2 /R 3 /Length 128 /O /U /P >>`. Header ≥ 1.4.
- **AES-128:** `<< /Filter /Standard /V 4 /R 4 /Length 128 /CF << /StdCF << /Type /CryptFilter /CFM /AESV2 /AuthEvent /DocOpen /Length 16 >> >> /StmF /StdCF /StrF /StdCF /O /U /P [/EncryptMetadata false] >>`. Header ≥ 1.6.
- **AES-256:** `<< /Filter /Standard /V 5 /R 6 /Length 256 /CF << /StdCF << /Type /CryptFilter /CFM /AESV3 /AuthEvent /DocOpen /Length 32 >> >> /StmF /StdCF /StrF /StdCF /O <48> /U <48> /OE <32> /UE <32> /Perms <16> /P [/EncryptMetadata false] >>`.
  - Header 1.7 with the catalog `/Extensions << /ADBE << /BaseVersion /1.7 /ExtensionLevel 8 >> >>` (through the overlay; qpdf's layout, probe P-1), or 2.0 without it when `min_version` is 2.0.
- **ID[0]:** the source's when present, otherwise seed-derived (§1.8). ID[1] is computed as today (D11.2).
- **Trailer keys:** `/AuthCode` and any other trailer key the writer does not know are not carried into encrypted output.

### 4.7 The page tree: flattening and the balanced rebuild
1. **Flatten.** It runs once per document, before the first insert, delete, move, reorder or import into it; `page_tree_flattened` is set.
   - For every page, in walk order, materialize the inheritable keys `/Resources /MediaBox /CropBox /Rotate` (§7.7.3.4) onto the page.
     - Use the value the walk inherits (M2 rule D11.5; the `/Parent`-chain value is also written when it differs, as the M2 setters do).
     - An inherited **direct** `/Resources` dictionary is promoted to one new indirect object per source node, shared by its pages.
     - `/Rotate 0` and `/CropBox = MediaBox` are written only when an ancestor had a different value.
   - A page listed a second time becomes a shallow copy: a new object whose `/Annots` is a new array of the same annotation references. Its `PageId` changes.
   - Root `/Kids` = the pages, `/Count` = n; every page's `/Parent` = root.
   - Inheritable keys are removed from the root. Intermediate nodes are `free`d.
2. **Rebuild on a full save** when `page_tree_flattened` is set (the overlay of `save_with`):
   - `K = 32` (D-10).
   - With n ≤ K, the root's kids are the pages.
   - Otherwise, level by level: `g = ⌈m/K⌉` nodes, sizes ⌊m/g⌋ or ⌈m/g⌉ (no node with fewer than ⌊m/g⌋ kids), until one level has ≤ K nodes, which become the root's `/Kids`.
   - New nodes are `<< /Type /Pages /Kids […] /Count c /Parent p >>`; the root keeps its object number.
   - Every kid's `/Parent` is the node that lists it (R-13 consistent), and every `/Count` is the number of leaves.
   - Zero pages give `<< /Type /Pages /Kids [] /Count 0 >>`.
3. **An incremental save** writes the flat tree as edited (no rebuild), as qpdf does.

### 4.8 Import (deep copy, iterative, bounded by `max_objects`)
- **Starting points:** the walk starts from each page dictionary and follows references; the session map is filled before descending (cycles).
- **Page objects are never copied implicitly.** A reference to a source page or `/Pages` node that is not being imported is written as `null`; a reference to one that is imported becomes the mapped page.
- **Keys handled specially on the page:**
  - `/Parent` is set to the target node;
  - `/StructParents` (pages and form XObjects) and `/StructParent` (annotations) are removed;
  - `/B` is removed;
  - `/Annots` is filtered as described in the next items.
- **Link annotations and `/OpenAction`-style destinations** to pages that are not imported are dropped.
  - Explicit destination arrays are remapped.
  - Named destinations, through the source `/Dests` or `/Names /Dests` (the model's `NameTree`), become explicit arrays.
  - `/IRT` to an annotation that is not imported is removed; annotation `/P` is set to the new page.
- **Widgets:**
  - field ancestors are copied without `/Kids`, and their `/Kids` are set to the imported widgets only (pypdf `_set_cloned_kids`);
  - signed signature fields are dropped with their widgets (P3).
- **Streams:**
  - `Source` data becomes `Encoded(source.encoded_stream_data())`: decrypted, filters kept;
  - `Encoded` and `Decoded` data are copied.
- **Optional content:** imported OCG dictionaries are appended to the target's `/OCProperties /OCGs`, and to `/D /OFF` when they are off in the source. `/OCProperties << /OCGs [] /D << >> >>` is created if absent.
- **Outlines** (`merge`, `extract`; `import_pages` when `outlines`):
  - pypdf filtering: a leaf to a page that is not imported is dropped; a parent with kept children keeps its title with no destination;
  - the result is written as new items appended under the target's root;
  - `/Count` is recomputed (closed items negative);
  - the walk uses a visited set and stops at `max_objects`.

### 4.9 Pruning after `delete_pages` (role-based, one bounded pass per call)
Removed pages are `free`d. Every fix below uses the set of removed page ids R:
- **Outline:** a leaf whose destination is in R is removed. Siblings `/Prev`/`/Next` and the parent's `/First`/`/Last` are relinked, and `/Count` is recomputed up the chain. A parent keeps its title with the destination removed.
- **Named destinations:**
  - entries in R are removed from catalog `/Dests` (dict) and from `/Names /Dests` leaves;
  - `/Limits` is recomputed on the touched leaves and ancestors;
  - a leaf that becomes empty is removed from its parent's `/Kids`.
- **`/OpenAction`** to R is removed.
- **Link annotations** on the remaining pages whose explicit, `GoTo` or named destination resolves into R are removed from `/Annots`.
- **AcroForm:**
  - widgets on removed pages are removed from their field's `/Kids`, or the merged field-widget from its parent `/Kids` or `/Fields`;
  - a non-terminal node left without kids is removed;
  - `/CO` is filtered.
- **Structure tree, threads:**
  - inside `/StructTreeRoot` (iterative, visited set), every `Ref` in R becomes `null`;
  - a thread with a bead on a removed page is removed from `/Threads`.
- **`/PageLabels`** are unchanged, with a warning (backlog M6).

### 4.10 AcroForm merge
- **No target AcroForm:** a copy of the source's is created (`/DR`, `/DA`, `/Q`, `/NeedAppearances`), with `/Fields` = the imported roots.
- **Root-name collisions:** an imported root whose `/T` text equals a target root's (or an earlier import's) is renamed to the smallest free `T#k`, k ≥ 2.
- **`/DR /Font`:**
  - a name the target lacks is added;
  - a name with the same mapped object is shared;
  - otherwise the source name is renamed `Name_k`, and every `/DA` of the imported fields and widgets has that name token rewritten (PDF lexer, `/Name … Tf`).
  - Other `/DR` categories: added when absent; on a collision the target's is kept, with a warning.
- **Inherited `/DA` and `/Q`:** the source AcroForm values are materialized onto imported roots that lack them.
- **`/NeedAppearances`:** true if either side has it, with a warning.
- **`/SigFlags`:** bit 1 if any signature field remains (bit 2 unchanged).
- **`/XFA`:** the source's is never copied; the target's is removed with a warning (P6).

## 5. Interactions

### 5.1 Signatures and page operations (D-3)
- **Methods covered:** every page-mutating `Document` method of M5, and the M2 setters `set_rotation`, `set_media_box` and `set_crop_box`.
- **The check:** `signature_state()`, which reads `/Perms /DocMDP`, and the AcroForm field tree for `/FT /Sig` with a `/V` dictionary. It is bounded by the limits.
- **Outcomes:**

  | State | Default | With `allow_invalidating_signatures` |
  |---|---|---|
  | `Certified` | `E_DOC_MDP_FORBIDS` (no P permits page changes: §12.8.2.2 Table 257) | allowed |
  | `Signed` | `E_SIGNED_DOCUMENT` | allowed |

- **After an allowed change:**
  - an incremental save keeps earlier signatures intact, and the verifier and pyHanko report them as `Other` (tests assert both);
  - a full save destroys them, as in M2.
- Importing **from** a signed source never needs the flag.

### 5.2 Incremental saves of encrypted files
- **What the update keeps:** it carries `/Encrypt` exactly as read, keeps `/ID[0]` and writes a new `/ID[1]`.
- **What gets encrypted:** every string and stream of every written object is encrypted with the file key and the object's own id. The exception is the update's cross-reference stream, which is never encrypted.
- **Refused:**
  - `structure_repaired()` and the existing D11 refusals;
  - inconsistent `/Encrypt` across revisions (§1.3);
  - an ISO 32004 MAC (`E_UNSUPPORTED`, E14);
  - an edit of the `/Encrypt` object (`E_INVALID_ARGUMENT`).
- **Edited source streams** still holding `Source` data are decrypted with their source id and re-encrypted with the same id (the general path, no byte copy, so a change of exemption is honoured).

### 5.3 Signing encrypted files
- **Requirement:** `prepare` and `sign` need a `Document` opened with a password, or an empty user password.
- **What is encrypted:**
  - the signature dictionary's strings (`/M`, `/Name`, `/Reason`, …), the field's `/T`, the appearance stream and the rewritten `/Annots`/AcroForm objects are encrypted;
  - `/Contents` stays a plain `<00…>` placeholder, because the predicate (§1.4) recognizes the overlay's signature dictionary.
- **Placeholder location:** the ByteRange placeholder and the `/Contents` search find the key token, never a value.
- **The prepared file** is already encrypted, so `finish`/`embed_cms` need no key and FXPS holds none (test `sign_encrypted_two_phase_fxps_has_no_key`).
- **Re-reading the prepared file** (`signature_dictionary_matches`) and revision views (`Revisions::open_view`) use `Store::open_with_security(prefix, opts, &ReuseDecryptor(store.decryptor()))`. A view whose binding differs is `None`, which makes the classifier `Other`.

### 5.4 The M4 verifier on encrypted files (what the classifier sees)
- **Decrypted values, raw bytes:**
  - objects are compared as the decrypting store shows them;
  - byte-level checks (ByteRange, layout, the canonical gate, the rebuild-proof scan, `/Size`) read the raw file, where ciphertext is hex.
- **Rules added to V10.** Each is a whitelist precondition; a failure is `Other` with a note:
  - **V-E1.** Every later trailer, and the cross-reference stream dictionary, keeps the signed revision's `/Encrypt` (same reference, the object not re-listed unless byte-identical) and `/ID[0]`.
  - **V-E2.** Every AES string and stream written after the signed revision has a ciphertext length ≥ 32 and ≡ 0 (mod 16). This is key-independent.
  - **V-E3.** No stream written after the signed revision has a `/Crypt` filter, except `/Crypt /Identity` on the catalog metadata when `EncryptMetadata` is false (the M4 XMP rule already lists it).
  - **V-E4.** In an encrypted file with `EncryptMetadata` true, any new or changed catalog `/Metadata` is `Other` (E15).
    - **Principle:** no decision may depend on the *decrypted bytes* of objects written after the signed revision beyond equality with signed values and the type of direct objects.
    - **Reason:** otherwise an attacker without the key splices victim ciphertext into an update and learns, from the level, whether it decrypts to well-formed XML or valid Flate (a format oracle, as in the XML Encryption attacks).
  - **V-E5.** Padding validity is never consulted. Strings decrypt as qpdf shows them.
  - **V-E6.** Revision views decrypt with the newest decryptor only through `ReuseDecryptor` (§5.3).
- **`verify_bytes`** on an encrypted file fails with `E_PASSWORD_REQUIRED`. Callers open with a password and call `verify(&doc)`; Node's `verifySignatures` works on a document opened with a password.

### 5.5 Permission enforcement (D-9; off by default, D5.2)
With `enforce_permissions` set and `access = User`, an operation refused by the bits below is `E_PERMISSION_DENIED`:

| Operation | Required bits |

## 9. Open decisions (recommendations; accept as a block)

1. **D-1, exemption predicate.**
   - One function in `folioxide_syntax::crypt`, shared by the reader and the writers.
   - The signature `/Contents` exemption uses the D11.16 predicate, not qpdf's narrower one (E7).
   - This replaces `Decryptor::is_exempt` from the A.3 sketch.
2. **D-2, no oracle.**
   - Padding is never observable (qpdf output, no error in either mode).
   - Only key-independent ciphertext defects produce diagnostics or strict errors.
   - V-E4: XMP changes in encrypted files are `Other` (E15, stricter than pyHanko).
3. **D-3, signature policy for page operations.**
   - Refuse on signed (`E_SIGNED_DOCUMENT`, a new `ErrorCode`) and certified (`E_DOC_MDP_FORBIDS`) files unless `allow_invalidating_signatures`.
   - Apply it to the M2 setters too.
   - Alternative: warn only, by returning reports.
4. **D-4, randomness.**
   - A caller seed for new R6 encryption.
   - Synthetic HMAC-derived IVs everywhere (§1.8).
   - No RNG parameter on the save functions.
5. **D-5, R5.** Read; keep an existing R5 dictionary on a full save and on incremental saves; never create one.
6. **D-6, ISO/TS 32004.**
   - Detect it.
   - Refuse incremental saves and signing.
   - A full save drops the MAC, sets P bit 13 and recomputes `/Perms`.
   - Verifying and writing MACs goes to the backlog.
7. **D-7, password candidates.** At most 2 candidates (§4.3). Bytes are used verbatim.
8. **D-8, owner password.**
   - It defaults to the user password.
   - A non-empty user password with an empty owner password is refused (E10).
   - Restricted permissions with an empty owner password, or one equal to the user password, are refused (they cannot be enforced).
9. **D-9, permission enforcement.** Implement `OpenOptions::enforce_permissions` (default false, D5.2) with the §5.5 table.
10. **D-10, page tree.**
    - Flatten on the first structural operation (qpdf parity).
    - Balanced rebuild with fanout 32 on a full save, through `writer::save_with`'s overlay.
    - Flat tree on incremental saves.
11. **D-11, blank page size.** The previous page's media box, else the next page's, else US Letter.
12. **D-12, links to pages that are not imported or were deleted.** Drop the link annotation (pypdf parity). This deviates from A.3 "→ Null"; destinations in other roles follow §4.8 and §4.9.
13. **D-13, signed signature fields on import.** Drop them with their widgets (P3).
14. **D-14, RC4.** The `rc4` 0.2.0 crate; fall back to an own 30-line implementation if its API does not fit.
15. **D-15, PDFDocEncoding.** Move the table to `folioxide-syntax::text::pdfdoc` (stage 0). The model's `text.rs` uses it, and the D11.6 behaviour is unchanged.
16. **D-16, string form.** Ciphertext strings are always hex. Decrypted strings keep their ciphertext token's form. Graph tests use `with_string_form(false)`.
17. **D-17, R6 header.** 1.7 with `/Extensions /ADBE` level 8, or 2.0 when asked.
18. **D-18, weak crypto.** RC4 writes need `allow_weak_crypto` (qpdf parity).
19. **D-19, AcroForm merge naming.**
    - Fields: `name#k` (A.3).
    - `/DR` fonts: `Name_k`, with `/DA` rewritten.
    - The target's `/XFA` is removed (P6).
20. **D-20, named destinations on import.** Make them explicit (P2).
21. **D-21, `ImportSession` identity.** A `Weak<DocIdentity>` plus an edit epoch; no global counter.
22. **D-22, new error code and diagnostics.**
    - Add `ErrorCode::SignedDocument` (if D-3 is accepted); no `E_PAGE_RANGE` or `E_ENCRYPTED`.
    - Add `DiagnosticKind::{Encryption, Ciphertext}`.
