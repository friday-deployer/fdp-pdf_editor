## Contracts between the packages
1. **Oracle runner CLI:** `python -I tools/oracles/run_suite.py <dir> [<dir>...]`.
   - It finds every `*.pdf` that has a sibling `<name>.expect.json`, runs the checks keyed by the JSON (see ARCHITECTURE §A.9 "Oracle mechanism") and prints a PASS/FAIL table.
   - Exit codes:
     - **0** when everything passes, *or* when no cases are found (it prints "no oracle cases")
     - **1** on any failure
     - **2** on usage or environment errors (a missing tool, or an unknown expect key)
2. **The venv** lives at `<repo>/.venv` and is created by `bash tools/setup-venv.sh`, which is idempotent. The interpreter is `.venv/bin/python`.
3. **`cargo xtask oracle [--suite <name>]`:**
   - runs `cargo test --workspace --features folioxide-testkit/emit` (in M0 this emits nothing), then runs `.venv/bin/python -I tools/oracles/run_suite.py target/oracle/<suite>`, or `target/oracle` when no suite is given
   - creates the directory if it is missing
   - if `.venv` is missing, exits 2 with the hint `run: bash tools/setup-venv.sh`
4. **`cargo xtask fixtures`:** regenerates the generated fixtures. In M0 it is a no-op that exits 0.
5. **`cargo xtask ci`:** runs the gate commands from CLAUDE.md in order (fmt check, clippy, test, deny if installed, the tree checks below).
6. **Test PKI** lives in `fixtures/pki/`. The password for every encrypted key and `.p12` is `folioxide`.
   - **Chain:** `root.pem`, `intermediate.pem`
   - **Signers**, each a cert plus a PKCS#8 key: `signer-rsa2048`, `signer-rsa3072`, `signer-p256`, `signer-p384`
   - **TSA:** `tsa.pem` plus key, with EKU `timeStamping` marked **critical** and issued by the root (`tsa-root.pem` may simply be a copy of or symlink to `root.pem`, but document which)
   - **Negative cases:** `expired.pem` (validity entirely in the past) and `wrong-ku.pem` (no digitalSignature/nonRepudiation)
   - **PKCS#12:** `signer-rsa2048-modern.p12` (OpenSSL 3 defaults: AES-256/PBKDF2, SHA-256 MAC), `signer-rsa2048-3des.p12`, `signer-rsa2048-rc2-40.p12` (`-legacy`) and `signer-p256-modern.p12`
   - **Validity:** use long validity for the non-expired certs, from 2025-01-01 to at least 2075.

## WP0.2 (Dev B): oracles, PKI, fixtures, CI
1. **`tools/requirements-dev.txt`** pins `pyhanko==0.37.0`, `pypdf==6.20.0`, `pikepdf==10.16.0`, plus any direct imports you use (e.g. `asn1crypto`, `pyyaml` for the CI-yaml self-check), all pinned. **`tools/setup-venv.sh`** is `set -euo pipefail` and idempotent, and creates `.venv` at the repo root.
2. **`tools/oracles/`:**
   - `run_suite.py`: the contract runner with a pluggable check registry
   - `check_pdf.py`, the structural checks:
     - `pdfinfo` exits 0
     - page count and version match
     - pikepdf open + `check()` finds no errors
     - pypdf `PdfReader(strict=True)` reads every page
     - info fields match `pdfinfo`
   - `validate_sig.py`, signature validation with pyHanko:
     - per-signature `intact`, `valid`, `trusted` (trust roots from the CLI or expect.json), `coverage`, `modification_level`, `docmdp_ok`
     - plus `pdfsig -nocert`
   - `extract_cms.py`: extracts `/Contents` DER and the signed byte ranges for `openssl cms -verify`
   - `pades_profile.py` (asn1crypto) reports and checks:
     - SubFilter
     - content-type, message-digest and signing-certificate-v2 present
     - signing-time absent
   - `text_check.py`: `pdftotext` contains or lacks given strings
   - each module is importable and has a CLI `main`
   - wire the expect keys `pages`, `version`, `info`, `signatures`, `textContains`, `textAbsent`, `prefixOf`, `revisions`
   - any other key in the §A.9 list gives a clear "check not implemented yet" (exit 2), not a silent pass
3. **Oracle self-tests** (`tools/oracles/tests/`, run with `.venv/bin/python -I -m unittest discover -s tools/oracles/tests`):
   - build a tiny valid PDF from hand-written bytes and check that the structural checks pass and that a corrupted copy fails
   - **sign it with pyHanko** using `fixtures/pki` (RSA-2048 and P-256), then show that `validate_sig.py`, `extract_cms.py` + `openssl cms -verify` and `pdfsig` accept it
   - flip one byte inside the signed range and show `intact=False`
   - this proves the oracles work before our own signer exists in M3
   - generated files go to a temp dir and are not committed
4. **`tools/gen-pki.sh`** (openssl, `set -euo pipefail`):
   - generates the PKI from the contract into `fixtures/pki/`
   - `--check` mode does **not** regenerate, because keys are random. Instead it validates the committed files:
     - `openssl verify -CAfile root.pem -untrusted intermediate.pem` passes for each signer
     - the expired cert really is expired
     - the TSA EKU is critical
     - every `.p12` opens with `openssl pkcs12 -info -noout -passin pass:folioxide [-legacy]`
   - `fixtures/pki/README.md` says these are test-only keys
   - also add `tools/tsa/openssl-tsa.cnf` so that `openssl ts -reply` works with the fixture TSA (prove it with a one-off command in your report)
5. **`fixtures/README.md`:**
   - the license policy: generated by this project and licensed `MIT OR Apache-2.0`; external corpora are never committed; OFL fonts may be used as test data only
   - a provenance table with one row per committed file or group
6. **`.github/workflows/`:**
   - `ci.yml`, with jobs:
     - `fmt`
     - `clippy`
     - `test` (matrix ubuntu-latest, macos-latest, windows-latest)
     - `deny` (`EmbarkStudios/cargo-deny-action`)
     - `node` (Node 22 + pnpm; `pnpm install --frozen-lockfile && pnpm build && pnpm test && pnpm test:types` in `bindings/node`)
