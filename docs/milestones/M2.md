# M2 brief: writers, document model v1, Node open/save

This brief is the source of truth for M2. It refines `docs/ROADMAP.md` § M2.
- **Design:** `docs/ARCHITECTURE.md` §A.3 (store, edits, full and incremental save rules), §A.4 (API style), §A.7 (Node), §A.8 (Tauri readiness), §A.10 (traps #10, #12, #17, #25).
- **Goal:** edit objects in a `Store`, save a document as a full rewrite or as an **incremental update that never touches the original bytes**, read the page tree with inheritance, read and write the Info dictionary, and open, inspect and save PDFs from Node.
- **Out of scope:**
  - page insertion, deletion or reordering (M5)
  - encryption (M5): saving a document opened from an encrypted file is impossible in M2, since such files do not open yet
  - XMP (M6)

## API contracts
Names are binding; add more API freely. Every options struct is `#[non_exhaustive]`, implements `Default` and has `with_*` setters.

### WP2.1: Store edit API (`folioxide_syntax::Store`)
- **Creating:** `Store::new_empty(version: (u8, u8)) -> Store` creates a store with no source, for brand-new documents. It has no revisions, and incremental save fails with `InvalidArgument`.
- **Read path:** `resolve`, `deref` and `stream_data` see edits first (§A.3 "read path"). An object's `Arc` handed out before an edit stays a snapshot.
- **Editing objects:**
  - `set(&mut self, id: ObjectId, obj: Object) -> Result<()>` replaces an object. The id must be in use, or must have been returned by `add`. A generation mismatch gives `InvalidArgument`.
  - `get_mut(&mut self, id) -> Result<&mut Object>` is copy-on-write: it clones the resolved object into the edit set.
  - `add(&mut self, obj: Object) -> ObjectId` returns the next unused number with gen 0. It respects `Limits::max_objects`; if that limit is hit it returns `Result` instead.
  - `free(&mut self, id) -> Result<()>` frees an object. The incremental writer emits a free entry with generation + 1 (gen 65535 stays 65535 and is never reused).
- **Editing the trailer:** `set_trailer_entry(&mut self, key: &[u8], value: Object) -> Result<()>` and `remove_trailer_entry`. These are allowed for `/Root`, `/Info` and `/ID`. The writer computes `/Size`, `/Prev`, `/XRefStm`, `/W`, `/Index`, `/Filter`, `/DecodeParms`, `/Length` and `/Type` itself and refuses user values for them.
- **Inspecting edits:** `is_modified() -> bool` and `edited_ids() -> Vec<ObjectId>` (sorted).
- **Generations:** `generation_of(num) -> Option<u16>` (current xref generation, for free-entry bumps).
- **Edited streams:** they carry `StreamData::Decoded` (encoded by the writer) or `StreamData::Encoded` (written as is, with the dictionary's `/Filter` kept). `stream_data` must work on edited streams too.

### WP2.1: writer (`folioxide_syntax::writer`, re-exported at the root)
- **`SaveOptions`** fields:
  - `xref: XrefStyle::{Auto, Table, Stream}`. `Auto` means a stream if object streams are on or the source used a stream, otherwise a table.
  - `object_streams: bool` (default false)
  - `compress: StreamCompression::{Keep, CompressNew, Recompress}` (default `CompressNew`, which Flate-encodes only `Decoded` data)
  - `gc: bool` (default true)
  - `renumber: bool` (default true: dense numbering from 1)
  - `deterministic: bool`
  - `id: Option<[Vec<u8>; 2]>`
  - `min_version: Option<(u8, u8)>`
  - `flate_level: u8` (default 6)
- **`save(store: &Store, opts: &SaveOptions) -> Result<Vec<u8>>`**, the full rewrite (also available as `Store::save`):
  1. GC from the trailer roots (`/Root`, `/Info`, `/Encrypt` is not possible in M2, `/ID` is direct).
  2. Optional renumbering.
  3. Header `%PDF-x.y` + `%` + 4 bytes ≥ 0x80 + EOL. The version is the maximum of the source header, the requested minimum, and 1.5 when xref or object streams are used. Junk before the source header is dropped.
  4. **Every source stream with `StreamData::Source` is copied as raw encoded bytes** (zero decode) unless `Recompress` is set.
  5. **Object-stream packing excludes:** streams, objects with gen ≠ 0, any object that is a `/Type /Sig` or `/Type /DocTimeStamp` dictionary, the `/Encrypt` dict and the xref stream itself. A container is limited to 256 objects.
  6. **`/ID`:** taken from `opts.id`, otherwise the source `/ID` with element 1 recomputed, otherwise generated. With no RNG in the core, a generated `/ID` is MD5 of a stable content digest (document this; uniqueness comes from the content).
  7. **Deterministic mode** gives byte-identical output for identical input and edits.
- **xref tables:** 20-byte entries `nnnnnnnnnn ggggg n\r\n`. The first subsection always starts at 0, with the object 0 free-list head: pypdf strict mode rejects tables that are not zero-indexed. Free entries form a proper linked list (§7.5.4).
- **`IncrementalOptions`:** `deterministic: bool` and `id1: Option<Vec<u8>>`.
- **`save_incremental(store, &IncrementalOptions) -> Result<Vec<u8>>` and `incremental_suffix(store, opts) -> Result<Vec<u8>>`**, where `save_incremental` = source bytes + suffix. The rules are ARCHITECTURE §A.3 "Incremental save" plus:
  - **Bytes:** the source is byte for byte untouched, including bytes before `%PDF-`. Add an EOL first if the source does not end in CR or LF.
  - **Content:** only edited, added and freed objects. Classic table after a table revision. **Xref stream after a stream or hybrid revision**: the new xref stream object gets its own number and covers itself.
  - **Offsets:** follow `store.offset_base()`. `HeaderRelative` offsets, the norm, count from the `%PDF-` header; `Absolute` offsets count from byte 0, as the source does. `/Prev` is the last revision's `startxref` value as stored in `Revision`.
  - **Trailer:** `/Prev` is the last revision's `startxref`. `/Size` is the max number + 1. `/Root`, `/Info` and `/ID` are carried over (or taken from trailer edits). `/ID` is `[orig0 new1]`.
  - **Refusals:**
    - when the store has no source (`InvalidArgument`)
    - when the last revision is `XrefKind::Reconstructed` **or `store.structure_repaired()` is true** (`Unsupported`, "full save required"). Appending to a structure that other readers may resolve differently is the reader-differential risk that M1 worked to close (DECISIONS D9.8).
    - when nothing was edited (it returns the source bytes unchanged, which is not an error)
  - **No compression in increments:** an incremental save never puts new objects into object streams and never compresses the existing source. Signatures (M3) depend on byte-exact control.
- **Writer helpers:** `Revision` gains whatever M3 needs to locate a revision's bytes. At minimum, document that `eof_end` of the last revision plus the suffix length gives the new file length.

### WP2.2 and WP2.3: `folioxide-model`
`folioxide-model` uses `folioxide_syntax::Error` and `ErrorCode` directly (codes `PageOutOfRange`, `NotFound`, `InvalidArgument`, …). A separate model error type is not needed unless you justify one.

**Document.** `pub struct Document`, which is `Send + Sync` (assert it):
- **Constructors:**
  - `Document::open(bytes: Vec<u8>, &OpenOptions) -> Result<Document>`
  - `Document::open_shared(SharedBytes, &OpenOptions)`
  - `Document::from_store(Store) -> Result<Document>`
  - (WP2.3) `Document::new() -> Document`, an empty valid PDF 1.7 with a catalog and an empty page tree. Saving it gives a file that `pdfinfo` accepts with `Pages: 0`; check what pdfinfo/qpdf say about zero pages and document it.
- **Accessors:** `store() -> &Store`, `store_mut() -> &mut Store`, `diagnostics() -> Vec<Diagnostic>`, `version() -> (u8, u8)` (the header, overridden by catalog `/Version` when it is higher), `catalog() -> Result<Arc<Object>>`.
- **Pages:**
  - `page_count() -> Result<usize>` uses the actual leaf walk, not `/Count`. A wrong `/Count` gives a diagnostic.
  - `page_ids() -> Result<Vec<PageId>>` uses a cached walk, invalidated whenever the page tree is edited.
  - `page(index: usize) -> Result<Page<'_>>`. An out-of-range index gives `PageOutOfRange`.
- **Page-tree walk:** iterative, with cycle detection (an `ObjectId` set) and `max_page_tree_depth`. Kids that are not `/Page` or `/Pages` are skipped with a diagnostic. A missing `/Type` on a leaf is tolerated.

**Page (read side, WP2.2).** `Page<'a>`:
- **Identity:** `id() -> PageId` (where `PageId(ObjectId)`) and `index()`.
- **Boxes:** `media_box() -> Rect`, which falls back to US Letter (612×792) with a diagnostic, and `crop_box()`, `bleed_box()`, `trim_box()`, `art_box()`. They follow the §14.11.2 defaults and are clipped to the MediaBox.
- **Rotation:** `rotation() -> Rotation`, an enum of `R0`, `R90`, `R180` and `R270`, normalized from any multiple of 90 including negatives. A value that is not a multiple of 90 gives a diagnostic and becomes R0.
- **Effective size:** `effective_size() -> (f64, f64)`, the crop box after rotation.
- **Resources:** `resources() -> Result<Option<Dict>>`.
- **Inheritance:** `/Resources`, `/MediaBox`, `/CropBox` and `/Rotate` are inherited (§7.7.3.4).
- **`Rect`:** `{ llx, lly, urx, ury }`, normalized (llx ≤ urx).

**Page setters (WP2.3).**
- `set_media_box(index, Rect)`, `set_crop_box(index, Option<Rect>)` and `set_rotation(index, Rotation)`.
- **Materialize before overriding:** when a value was inherited, the setter writes it on the leaf (§7.7.3.4).

**Info (§14.3.3).**
- **Reading (WP2.2):** `info() -> Result<DocInfo>` returns `DocInfo { title, author, subject, keywords, creator, producer: Option<String>, creation_date, mod_date: Option<PdfDate>, trapped: Option<Trapped>, custom: BTreeMap<String, String> }`. All strings are decoded text strings.
- **Writing (WP2.3):** `set_info(&InfoUpdate) -> Result<()>`.
  - `InfoUpdate` has one `Option<Option<..>>` per field: `None` keeps the value, `Some(None)` removes it, `Some(Some(v))` sets it.
  - The Info dictionary is created and linked through the trailer if it is missing.
  - Values use `encode_text_string`.
  - Setting the Info dictionary does **not** set `/ModDate` automatically, because the core has no clock. The caller passes it.

**Text strings, dates and trees (WP2.2).**
- **Text strings:** `text::decode_text_string(&[u8]) -> String` handles the UTF-16BE BOM, the UTF-8 BOM (PDF 2.0) and PDFDocEncoding (the full table, §D.3). It is lossy; invalid sequences become U+FFFD.
- `text::encode_text_string(&str) -> Vec<u8>` uses PDFDocEncoding when every character maps, otherwise UTF-16BE with a BOM.
- **Dates:** `PdfDate` provides `parse(&[u8]) -> Option<PdfDate>`, lenient with partial forms, an optional `D:`, the trailing apostrophe, and `Z`/`+`/`-` offsets. It also provides `to_pdf_string()` and `to_rfc3339()`, and has public fields: year, month, day, hour, minute, second, and an offset in minutes as `Option<i32>`.
- **Trees:** `NameTree::new(&Store, root: &Object)` and `NumberTree::new(..)` provide `get(key)` and `entries() -> Result<Vec<(Key, Object)>>`. They detect cycles, respect the depth limit, and are bounded by `max_objects`.

**DTOs (WP2.3).**
- `DocInfo`, `Rect`, `Rotation`, `PageInfo { index, width, height, mediaBox, cropBox, rotation }` and `InfoUpdate` derive `Serialize`/`Deserialize` behind the model crate's `serde` feature, with `rename_all = "camelCase"`.
- The facade's `serde` feature turns them on.

**Facade (`crates/folioxide`).**
- `pub use folioxide_model::{Document, Page, PageId, Rect, Rotation, DocInfo, InfoUpdate, PdfDate}`.
- `pub use folioxide_syntax::{Error, ErrorCode, OpenOptions, SaveOptions, IncrementalOptions, Diagnostic, Limits, Strictness}`.
- Keep `VERSION`. A unified `folioxide::Error` enum is only needed once a second error type exists (M3); until then, re-export the syntax error.

### WP2.5: Node (`bindings/node`)
- **`PdfDocument`:**
  - static `open(data: Uint8Array, opts?: { strict?: boolean })` and `openAsync(...)`, plus static `create()`
  - getters `pageCount`, `version` (string like `"1.7"`) and `isModified`
  - methods `diagnostics(): Diagnostic[]`, `getPage(i): PageInfo`, `getInfo(): DocInfo`, `setInfo(update: InfoUpdate)`, `setPageRotation(i, deg)`, `setPageBox(i, 'media'|'crop', box|null)`
  - `save(opts?: SaveOptions): Buffer` and `saveAsync(opts?)`, `saveIncremental(): Buffer` and `saveIncrementalAsync()`
  - In `InfoUpdate`, `undefined` keeps a value and `null` removes it. Dates are passed as PDF date strings or JS `Date` (convert in the JS facade).
- **Errors:** every thrown error has `code = "E_" + ErrorCode` (SCREAMING_SNAKE). Sync methods use `try_lock` and throw `E_BUSY` while an async task holds the document (§A.7).
- **TypeScript and tests:** generated `binding.d.ts` plus a hand-written `index.d.ts` with JSDoc. Tests `test/open-save.test.mjs` and `test/errors.test.mjs` use committed fixtures (`fixtures/syntax/*.pdf`). Type tests are updated.

   - every full and incremental output passes `pdfinfo`, the pikepdf/qpdf check (no errors) and pypdf strict
   - `pages` and `info.Title` match
   - every incremental output has the `prefixOf` check against its source and `revisions` = source + 1

5. **Oracle suite `model`:** for a fixture with inherited boxes and rotation, `pdfinfo -box -f 1 -l N` agrees with our `PageInfo` for every page (a new `boxes` expect key).
6. **Node:** `pnpm build && pnpm test && pnpm test:types` pass in `bindings/node`, including:
   - an open/save round trip
   - a `saveIncremental` prefix check done in JS
   - a `setInfo`/`getInfo` round trip with non-Latin text (UTF-16)
   - an invalid input throwing `code === "E_SYNTAX"` or `"E_XREF"`

   - a sync call during `saveAsync` throwing `E_BUSY` or completing without deadlock
7. **Robustness:**
   - no panics: the mutated-input harness also runs `Document::open` → `page_count` → every `page(i).media_box()` → full save
   - every recursive walk is bounded
   - writer output for every fixture reopens with no new diagnostics beyond those of the source
8. **Docs:** every public item is documented, ARCHITECTURE §A.3, §A.7 and §A.8 are updated where the implementation differs, and `docs/ROADMAP.md` is untouched (the manager updates it).
